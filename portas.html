Publicando portas (-p)

Um container tem a rede isolada própria: o Nginx dentro dele abre a porta 80, mas isso só existe lá dentro. Para acessar de fora (navegador, curl, outro programa), você publica a porta do container numa porta da sua máquina com -p.

Você vai aprender
  • O formato -p HOST:CONTAINER e a anatomia de -p 8080:80.
  • Publicar só no localhost: -p 127.0.0.1:8080:80 (mais seguro).
  • Porta aleatória no host: -p 80 e -P (publish all).
  • Protocolo UDP: -p 53:53/udp.
  • Ver o mapeamento com docker ps (coluna PORTS) e docker port.
  • Erros reais: porta já em uso no host (port is already allocated).

A cena: o site da Ana não abre

Ela subiu o Nginx assim (só com -d):

$ docker run -d --name meu-site nginx:alpine
$ docker ps
CONTAINER ID   IMAGE          STATUS         PORTS     NAMES
f3a1b2c3d4e5   nginx:alpine   Up 5 seconds   80/tcp    meu-site
$ curl -s http://localhost:80
curl: (7) Failed to connect to localhost port 80 … Connection refused

O 80/tcp na coluna PORTS é a porta que o container expõe na rede interna dele — ainda não está publicada no seu computador. Abrir http://localhost dá "connection refused".

O formato: -p HOST:CONTAINER

Missão: suba o Nginx publicando a porta: docker run -d -p 8080:80 --name meu-site nginx:alpine. Depois rode docker ps e veja o container Up 2 minutes com a porta mapeada.

$ docker run -d -p 8080:80 --name meu-site nginx:alpine
f3a1b2c3d4e5…
$ docker ps
CONTAINER ID   IMAGE          STATUS         PORTS                   NAMES
f3a1b2c3d4e5   nginx:alpine   Up 5 seconds   0.0.0.0:8080->80/tcp    meu-site
$ curl -s http://localhost:8080 | head -3
<!DOCTYPE html>
<html>
<head><title>Welcome to nginx!</title>…
-p
publish: "publica uma porta do container no host".
8080
A porta da sua máquina (host) que vai receber o acesso.
80
A porta do container para onde o acesso é encaminhado (o Nginx ouve 80).
0.0.0.0:8080->80/tcp
Como aparece no ps: qualquer IP da máquina na porta 8080 vai para a 80 do container.

A regra mental: esquerda = sua máquina, direita = container. -p 8080:80 lê-se "minha 8080 aponta para a 80 dele".

Variações

$ docker run -d -p 127.0.0.1:8080:80 nginx:alpine  « só o localhost acessa (mais seguro)
$ docker ps
… PORTS
… 127.0.0.1:8080->80/tcp
$ docker run -d -p 80 nginx:alpine                « porta ALEATÓRIA no host → 80 do container
$ docker ps
… PORTS
… 0.0.0.0:32768->80/tcp     « o Docker escolheu a 32768 para você
$ docker run -d -P nginx:alpine                   « -P = publica TODAS as portas expostas pela imagem, em portas aleatórias
$ docker run -d -p 53:53/udp imagem-dns           « protocolo UDP (padrão é TCP; escreva /udp no fim)
$ docker port meu-site                            « mostra só o mapeamento de portas do container
8080/tcp -> 0.0.0.0:8080
FormaQuando usar
-p 8080:80O caso comum: porta fixa e conhecida no host (site local, API).
-p 127.0.0.1:8080:80Quando só você deve acessar (banco de dados, painel admin) — ninguém de fora chega.
-p 80 / -PQuando a porta do host não importa (testes rápidos); veja qual foi no ps.
-p 53:53/udpServiços UDP (DNS, alguns jogos, VoIP).
várias portas-p 8080:80 -p 8443:443 (repete a flag, uma por porta).

Exemplos reais

Site estático (Nginx)

$ docker run -d -p 8080:80 --name site nginx:alpine
$ # abra http://localhost:8080 no navegador

API Node

$ docker run -d -p 3000:3000 --name api node:22-alpine node server.js
$ curl http://localhost:3000/ola
ola

Banco Postgres (só localhost!)

$ docker run -d -p 127.0.0.1:5432:5432 -e POSTGRES_PASSWORD=segredo --name banco postgres:16-alpine
$ psql -h localhost -p 5432 -U postgres   « conecta do seu computador
$ # de fora da máquina, ninguém alcança o banco ✅

Erros reais

Porta do host já está em uso 
$ docker run -d -p 8080:80 --name site2 nginx:alpine
docker: Error response from daemon: driver failed programming external connectivity on endpoint site2 (…): Bind for 0.0.0.0:8080 failed: port is already allocated

Já tem algo usando a 8080 na sua máquina (outro container ou um programa local — veja com sudo ss -ltnp | grep 8080). Como consertar: escolha outra porta do host (-p 8081:80) ou pare o que está usando a 8080.

Porta baixa no host (< 1024) pode pedir permissão

Publicar -p 80:80 no Linux pode exigir root para o host (portas abaixo de 1024 são privilegiadas). Solução: use uma porta alta no host (-p 8080:80) — é o padrão.

Publiquei a porta, mas o serviço não responde

Verifique duas coisas: (1) o programa dentro do container está ouvindo na porta certa? (ex.: docker exec web netstat -ltn ou ss -ltn); (2) você mapeou a porta certa? -p 8080:80 manda para a 80 do container — se o app ouve na 3000, é -p 8080:3000.

EXPOSE não publica porta

A instrução EXPOSE 80 do Dockerfile só documenta a porta (aparece no docker ps como 80/tcp) — ela não publica nada no host. Publicar é só com -p no run (ou ports: no Compose).

O que significa -p 8080:80?

Por que -p 127.0.0.1:5432:5432 é a forma mais segura de publicar um banco?

No docker ps, aparece 0.0.0.0:8080->80/tcp. O que isso quer dizer?

Publicando várias portas de uma vez

Repita a flag -p para cada porta (é uma opção de list — lembra do --help?):

$ docker run -d --name site-completo \
    -p 8080:80 \
    -p 8443:443 \
    nginx:alpine
$ docker ps
… PORTS
… 0.0.0.0:8080->80/tcp, 0.0.0.0:8443->443/tcp
$ docker port site-completo
80/tcp -> 0.0.0.0:8080
443/tcp -> 0.0.0.0:8443

E no Compose?

Quando o projeto sobe com docker compose up (nível 2), as portas vão no arquivo YAML em vez da linha de comando:

services:
  web:
    image: nginx:alpine
    ports:
      - "8080:80"     # mesma regra: HOST:CONTAINER
      - "127.0.0.1:8443:443"

Aula Serviços no Compose mostra isso e muito mais.

IPv6

Se o container também ouve em IPv6, o ps mostra as duas linhas: :::8080->80/tcp (o :: é o "0.0.0.0" do IPv6). Em hosts com IPv6 ligado, às vezes é preciso publicar assim explicitamente: -p [::1]:8080:80 (só IPv6 local).

Nunca publique banco de dados na internet

Publicar -p 5432:5432 (sem o 127.0.0.1) deixa o Postgres acessível para qualquer um que saiba o IP da sua máquina — e bots escaneiam a internet inteira procurando portas de banco abertas. Regra: banco e serviços internos sempre com 127.0.0.1 (ou numa rede Docker privada, nível 2). Só publique de verdade o que for público (site, API) — e mesmo assim, atrás de HTTPS.

Testando se a porta publicó (curl e ss)

Depois do run -p, confirme de dois jeitos:

$ curl -s -o /dev/null -w "%{http_code}\n" http://localhost:8080
200                       « o Nginx respondió HTTP 200
$ ss -ltnp | grep 8080    « quem está ouvindo na 8080 da sua máquina (Linux)
LISTEN 0  511  0.0.0.0:8080  0.0.0.0:*  users:(("docker-proxy",pid=…))
$ docker port meu-site    « o mapeamento que o Docker registrou
80/tcp -> 0.0.0.0:8080

Não dá para mudar o -p depois

O -p só existe na hora de criar o container (docker run ou create). Num container que já existe, não dá para adicionar porta: é preciso recriar (docker rm + docker run com o -p novo). Por isso vale pensar nas portas antes — ou usar Compose, onde o ports: fica no arquivo e você só dá up de novo.

Conflito de porta é o erro nº 1 de iniciante

Se localhost:8080 já abre outra coisa (ou outro container já publicó 8080), o run novo falha com port is already allocated. Veja quem está usando com ss -ltnp | grep 8080 (Linux) ou netstat -ano | findstr 8080 (Windows) e escolha outra porta do host (-p 8081:80).

Mesma porta em dois containers?

Dois containers podem ouvir a mesma porta interna (cada um na sua rede isolada — ex.: dois Nginx ouvindo 80). O conflito só existe no host: não dá para publicar -p 8080:80 duas vezes na mesma máquina. A solução é dar portas diferentes no host:

$ docker run -d -p 8080:80 --name site1 nginx:alpine
$ docker run -d -p 8081:80 --name site2 nginx:alpine   « mesma porta interna (80), portas diferentes no host
$ docker ps
… PORTS
… 0.0.0.0:8080->80/tcp   site1
… 0.0.0.0:8081->80/tcp   site2

Resumo

  • Container tem rede isolada: para acessar de fora, publique com -p HOST:CONTAINER (esquerda = sua máquina, direita = container).
  • -p 8080:80 → http://localhost:8080 chega na porta 80 do container. No ps aparece 0.0.0.0:8080->80/tcp.
  • Segurança: -p 127.0.0.1:… publica só no localhost (use para bancos). -p 80/-P = porta aleatória no host. /udp para protocolo UDP.
  • Veja o mapeamento com docker ps (PORTS) e docker port NOME.
  • Erros reais: Bind for 0.0.0.0:8080 failed: port is already allocated (porta do host ocupada — troque a porta do host) e porta <1024 pode exigir root.
  • EXPOSE no Dockerfile só documenta — não publica; publicar é -p.
