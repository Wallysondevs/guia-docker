docker ps — listando containers

Depois de rodar alguns containers com docker run, você precisa vê-los. O docker ps é a lista dos containers rodando agora. Com -a, aparecem todos, inclusive os que já pararam. Pense nele como o "gerenciador de tarefas" do Docker.

Você vai aprender
  • docker ps (só os rodando) e docker ps -a (todos).
  • A ler cada coluna: CONTAINER ID, IMAGE, COMMAND, CREATED, STATUS, PORTS, NAMES.
  • Os status: Up, Exited (0), Exited (1), Created, Restarting.
  • Variações: -q, -l, -s, --format.
  • Usar o ID curto no lugar do nome, e docker ps em scripts.

A cena: a Ana subiu três serviços

Depois da aula de docker run, a Ana subiu no notebook dela um site, um cache e um banco para testar o projeto novo:

$ docker run -d --name web   nginx:alpine
$ docker run -d --name cache redis:7-alpine
$ docker run -d --name banco postgres:16-alpine

Agora ela quer ver o que está no ar:

Missão: rode docker ps para ver os containers rodando agora.

$ docker ps
CONTAINER ID   IMAGE              COMMAND                  CREATED          STATUS          PORTS      NAMES
a1b2c3d4e5f6   nginx:alpine       "/docker-entrypoint.…"   10 seconds ago   Up 10 seconds   80/tcp     web
b2c3d4e5f6a1   redis:7-alpine     "docker-entrypoint.s…"   8 seconds ago    Up 8 seconds    6379/tcp   cache
d4e5f6a1b2c3   postgres:16-alpine "docker-entrypoint.s…"   5 seconds ago    Up 5 seconds    5432/tcp   banco

Três linhas, três containers rodando. Cada coluna responde uma pergunta:

As colunas, uma a uma

CONTAINER ID
Os primeiros 12 caracteres do ID único (um hash de 64 caracteres no fundo). Dá para usar esse pedaço no lugar do nome: docker stop a1b2c3d4e5f6 funciona igual.
IMAGE
A imagem que originou o container (nginx:alpine etc.).
COMMAND
O comando que o container está rodando agora (o padrão da imagem ou o que você passou depois do nome da imagem no run).
CREATED
Quanto tempo atrás o container foi criado (não é quando começou a rodar).
STATUS
A estado atual — a coluna mais importante (tabela abaixo).
PORTS
Portas que o container expõe dentro da rede dele (ex.: 80/tcp) e, se você publicó com -p, o mapeamento 0.0.0.0:8080->80/tcp.
NAMES
O nome: o que você pôs em --name ou o aleatório que o Docker inventou.

-a: todos os containers (inclusive parados)

O -a (de all) é o que você mais vai usar depois do ps puro, porque é onde aparecem os containers que já terminaram:

Missão: rode docker run --rm hello-world e depois docker ps -a — com --rm o container some, então rode docker run hello-world (sem --rm) antes para ver um "Exited" na lista.

$ docker run hello-world        « sem --rm: o container fica parado depois
$ docker ps
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES   « vazio: nada rodando
$ docker ps -a
CONTAINER ID   IMAGE          STATUS                       PORTS     NAMES
a1b2c3d4e5f6   nginx:alpine   Up 2 minutes                 80/tcp    web
c3d4e5f6a1b2   hello-world    Exited (0) 10 seconds ago            wizardly_curie

Agora sim: o web continua Up e o hello-world aparece como Exited (0).

Missão: suba um container novo (docker run -d --name cache redis:7-alpine) e depois rode docker ps — a coluna STATUS vai mostrar Up 2 minutes.

Variações úteis

ComandoO que faz
docker psSó os containers rodando.
docker ps -aTodos (rodando + parados).
docker ps -qSó os IDs, um por linha (útil em scripts: docker rm $(docker ps -aq)).
docker ps -lSó o último container criado.
docker ps -sMostra também o tamanho em disco de cada container.
docker ps --format "{{.Names}}: {{.Status}}"Saída personalizada (template Go) — ex.: web: Up 2 minutes.
docker ps --filter "name=web"Filtra por nome (status=running, ancestor=nginx…).
$ docker ps --format "{{.Names}} está {{.Status}}"
web está Up 2 minutes
cache está Up 2 minutes
banco está Up 2 minutes

Usando o ID curto e scripts

Você não precisa digitar o nome inteiro: os primeiros caracteres do ID bastam (desde que não haja ambiguidade):

$ docker stop a1b2          « os 4 primeiros caracteres já bastam
web

E dá para encadear comandos com $(...) — o famoso "limpa tudo que estiver parado":

$ docker rm $(docker ps -aq)    « -aq = todos os IDs, só de containers parados? não: de TODOS; use com cuidado
$ docker rm $(docker ps -q)     « só os rodando (para parar primeiro: docker stop $(docker ps -q))
Cuidado com docker rm $(docker ps -aq)

Esse comando apaga TODOS os containers parados da máquina — inclusive os de outros projetos que você queria manter parados. Antes de rodar, olhe o que vai ser apagado com docker ps -a. E container rodando não sai nesse comando: primeiro docker stop $(docker ps -q).

docker ps vazio não é erro

Se a lista vier só com o cabeçalho, não é bug: é que não tem nenhum container rodando agora. Rode docker ps -a para ver se há containers parados.

Exemplo completo: portas publicadas aparecem no ps

Quando você publica porta com -p (aula Portas), a coluna PORTS mostra o mapeamento completo:

$ docker run -d -p 8080:80 --name meu-site nginx:alpine
$ docker run -d -p 127.0.0.1:5432:5432 --name banco postgres:16-alpine
$ docker ps
CONTAINER ID   IMAGE              STATUS         PORTS                           NAMES
f3a1b2c3d4e5   nginx:alpine       Up 5 seconds   0.0.0.0:8080->80/tcp            meu-site
d4e5f6a1b2c3   postgres:16-alpine Up 3 seconds   127.0.0.1:5432->5432/tcp        banco

Leia a coluna PORTS assim: IP_DO_HOST:PORTA_DO_HOST->PORTA_DO_CONTAINER/protocolo. Ou seja: o Nginx responde na porta 8080 de todas as interfaces da máquina (0.0.0.0), e o Postgres só no localhost (127.0.0.1) — mais seguro para um banco.

Sem -p, a porta fica só interna

$ docker run -d --name interno nginx:alpine
$ docker ps
… PORTS
… 80/tcp                     « só 80/tcp: o container expõe 80 na rede interna dele, mas nada publicado no host

Nesse caso o site não abre em localhost — só outros containers na mesma rede alcançariam. Publicar é com -p.

O ciclo de vida visto pelo ps

Acompanhe um mesmo container pelas fases — é o jeito mais fácil de entender os status:

$ docker create --name ciclo hello-world     « só criou
$ docker ps -a
… STATUS     NAMES
… Created    ciclo
$ docker start ciclo                          « ligou
$ docker ps
… (vazio: já saiu na hora)
$ docker ps -a
… STATUS                    NAMES
… Exited (0) 2 seconds ago   ciclo
$ docker start ciclo                          « religa o MESMO container
$ docker ps -a
… Exited (0) 5 seconds ago   ciclo
$ docker rm ciclo                             « apagou de vez
$ docker ps -a                                   « não aparece mais
ComandoStatus no ps -a depois
docker create nome imgCreated
docker start nome (container que fica vivo)some do ps -a? não: aparece no ps como Up
docker start nome (container que sai na hora, tipo hello-world)Exited (0)
docker stop nomeExited (0) (ou Exited (143) se foi SIGTERM forçado)
docker kill nomeExited (137)
docker rm nomesome da lista

Filtros na prática

Além de -a e -q, dá para filtrar a lista sem escrever código:

$ docker ps --filter "name=web"            « só containers cujo nome contém "web"
$ docker ps --filter "ancestor=nginx:alpine"  « só containers criados dessa imagem
$ docker ps -a --filter "status=exited"     « só os que pararam
$ docker ps --filter "publish=8080"        « só os que publicaram a 8080
$ docker ps -a --filter "exited=1"         « só os que saíram com código 1 (erro) — olhe os logs deles!

Lendo a saída com --format

O --format usa um mini-template com campos entre {{ }}:

CampoMostra
{{.ID}}ID curto do container
{{.Image}}A imagem
{{.Names}}O nome
{{.Status}}O status (Up / Exited…)
{{.Ports}}As portas publicadas
{{.RunningFor}}Há quanto tempo está rodando
$ docker ps --format "{{.Names}} ({{.Image}}): {{.Status}} — portas: {{.Ports}}"
web (nginx:alpine): Up 2 minutes — portas: 0.0.0.0:8080->80/tcp
cache (redis:7-alpine): Up 2 minutes — portas: 6379/tcp

Resumo

  • docker ps = containers rodando; docker ps -a = todos (rodando + parados).
  • Colunas: CONTAINER ID (12 primeiros caracteres bastam), IMAGE, COMMAND, CREATED, STATUS, PORTS, NAMES.
  • Status: Up (rodando), Exited (0) (terminou com sucesso), Exited (1) (erro — veja logs), Created, Restarting.
  • Variações: -q (só IDs), -l (último), -s (tamanho), --format (saída própria), --filter.
  • Em scripts: docker stop $(docker ps -q), docker rm $(docker ps -aq) — com cuidado para não apagar o que não deve.
