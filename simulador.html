Terminal Simulado

Este guia tem um terminal Docker simulado que roda dentro da própria página: uma máquina fictícia ana@notebook com imagens e containers de mentira. Nada do que você digitar sai do navegador — pode errar à vontade. Um clique em Reiniciar e tudo volta ao estado inicial.

Você vai aprender
  • Como usar a caixa "Experimente": clicar, digitar, Enter.
  • O que é cada parte da janela: prompt ana@notebook:~$, linhas de comando, saída, mensagem de boas-vindas.
  • Teclas úteis: ↑/↓ (histórico), Ctrl+L (limpar), Ctrl+C (cancelar).
  • O botão Reiniciar e o botão Ver comando (quando há missão).
  • Como as missões são verificadas (selo verde "✔ Missão cumprida!").
  • O que o simulador sabe fazer e o que ele não sabe (para não confiar cegamente).

Por que um terminal simulado?

O medo de "quebrar alguma coisa" é o que mais trava quem está começando. No seu computador de verdade, um comando errado pode travar um serviço ou encher o disco; aqui esse medo não existe: o simulador é um programa dentro da página da web, não o seu Docker. Você pode apagar imagens, parar containers, rodar comandos errados, digitar cualquier coisa. Ao clicar em Reiniciar, a máquina volta ao estado inicial.

O objetivo é você perder o medo do terminal e ganhar memória muscular: depois de rodar docker run, docker ps e docker rm dez vezes aqui, na hora de usar o Docker de verdade (instalado na sua máquina) os comandos já saem sozinhos.

Anatomia da janela do terminal

Toda caixa escura de "Experimente" tem as mesmas peças:

┌─────────────────────────────────────────────┐
│ [Reiniciar] [Ver comando]        ← botões   │
│ ─────────────────────────────────────────── │
│ Máquina fictícia ana@notebook — Docker …   │  ← boas-vindas
│                                             │
│ ana@notebook:~$ docker images        ← comando digitado (com prompt)
│ REPOSITORY   TAG   IMAGE ID   …      ← saída do comando
│ ana@notebook:~$ _                    ← prompt esperando
└─────────────────────────────────────────────┘
ana@notebook:~$
O prompt: usuária ana, máquina notebook, pasta atual ~ (a casa da Ana). Tudo depois do $ é o que você digita.
linha verde/azul de comando
O comando que você digitou, repetido com o prompt na frente (para você ler o histórico da sessão).
linhas de saída
A resposta do comando. Linhas que começam com Error, Unable, No such etc. aparecem em destaque vermelho.
✔ Missão cumprida!
O selo verde que aparece quando a saída da sua caixa contém o trecho esperado da missão.

Usando a caixa "Experimente"

  1. Clique dentro da janela escura do terminal (o cursor passa a piscar).
  2. Digite um comando, por exemplo docker ps, e aperte Enter.
  3. Leia a resposta. Um prompt novo aparece quando o comando termina.
  4. Se a caixa tiver uma missão (texto "Missão:" em cima), um selo verde aparece quando você acerta.

Missão: digite docker ps -a e aperte Enter para listar todos os containers (inclusive os parados).

Botões da janela

Reiniciar
Apaga todo o histórico e devolve a máquina ao estado inicial: as 6 imagens pré-carregadas (hello-world, nginx:alpine, node:22-alpine, postgres:16-alpine, redis:7-alpine, python:3.12-slim) e nenhum container. Use quando quiser recomeçar a misión do zero.
Ver comando
Preenche o campo de entrada com o comando da missão (aparece só nas caixas com data-solucao). Útil quando você travou: é só apertar Enter depois.

Uma sessão completa de exemplo

Assim fica uma Sessão típica no simulador — rode você também:

$ docker run hello-world
7d3a1b9c2e4f

Hello from Docker!
This message shows that your installation appears to be working correctly.
…
$ docker ps -a
CONTAINER ID   IMAGE         COMMAND    CREATED          STATUS                      PORTS   NAMES
7d3a1b9c2e4f   hello-world   "/hello"   20 seconds ago   Exited (0) 18 seconds ago           clever_curie-42
$ docker rm clever_curie-42
clever_curie-42
$ docker ps -a
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES

Repare no fluxo: run criou e rodou; o container terminou sozinho (a imagem hello-world só imprime a mensagem e sai); ps -a mostrou ele parado (Exited (0)); rm apagou; a lista ficou vazia de novo.

O que o simulador sabe

Os principais comandos do Docker CLI, com estado fictício de imagens, containers, redes e volumes na máquina da Ana:

  • docker run (com -d, -it, --name, -p, -e, -v, --rm, --network)
  • docker ps (-a), docker images, docker pull, docker stop/start/restart, docker rm, docker rmi
  • docker logs, docker exec, docker inspect, docker stats
  • docker build, docker tag, docker network, docker volume, docker system df/prune, docker compose, docker info, docker version, docker --version, docker --help, docker CMD --help
  • Comandos de shell básicos: clear, echo, help, exit, history, sudo docker …

Missão: digite help dentro da caixa para ver a lista de comandos que o simulador aceita.

$ help
Comandos disponíveis: docker (run, ps, images, pull, stop, rm, rmi, logs, exec, build, network, volume, compose, system, ...), clear, echo, help, exit, history

O que ele NÃO sabe (leia antes de confiar)

  • Não fala com a internet: docker push e docker login são simulados (sempre dão certo, sem enviar nada).
  • Não baixa imagens de verdade: docker pull de imagens novas cria uma entrada fictícia (~100MB); a saída imita o formato real ("Pulling from library/…", "Status: Downloaded newer image").
  • Não roda containers de verdade: docker exec -it … sh mostra uma mensagem em vez de abrir um shell; docker run -p … não abre porta de verdade (não dá para acessar no navegador).
  • Dados de docker stats, docker system df e os IDs/nomes aleatórios são fictícios (mas no formato real).
  • Erros de digitação de comandodeaqui são limitados: um subcomando desconhecido responde docker: '…' is not a docker command.
Use o simulador para aprender a forma dos comandos — e o Docker de verdade para o resto

Tudo o que aparece nas caixas pre.term (fora do simulador) foi conferido no Docker Engine 27 real. Quando quiser ir além do simulador — subir um site de verdade, conectar no banco — instale o Docker na sua máquina (aula de instalação) e rode os mesmos comandos no terminal dela.

Erros que o simulador mostra de propósito

Parte de aprender é errar. Estes são os erros mais comuns que você vai ver (todos no formato real do Docker):

$ docker stop nao-existe
Error response from daemon: No such container: nao-existe
$ docker rm meu-site        « se meu-site estiver rodando…
Error response from daemon: cannot remove container "meu-site": container is running: stop the container before removing or force remove
$ docker run              « esqueceu a imagem
docker: 'docker run' requires at least 1 argument.
See 'docker run --help'.
$ docker abracadabra
docker: 'abracadabra' is not a docker command.
See 'docker --help'.

Na dúvida, docker --help lista todos os comandos e docker COMANDO --help mostra as opções de um comando específico — a aula Obtendo ajuda detalha.

Dicas de uso

  • Cada página tem suas próprias caixas — o estado (imagens e containers) é compartilhado entre as caixas da mesma página, então o que você rodou numa caixa aparece na outra (por isso dá para dar run numa caixa e ps na seguinte).
  • Se travar numa missão, clique em Ver comando e aperte Enter.
  • Se a máquina ficou uma bagunça, Reiniciar devolve tudo ao estado inicial na hora.
  • Os IDs e nomes aleatórios (tipo clever_curie-42) mudam a cada vez — no Docker de verdade é a mesma coisa.

Pratique

Missão: rode docker run hello-world. É o "Olá, mundo!" do Docker — um container que imprime uma mensagem e sai.

Perguntas rápidas sobre o simulador

Posso quebrar o simulador?

Pode. A pior coisa que acontece é a página recarregar e você perder o histórico da caixa — clique em Reiniciar e volta tudo. Nada afeta seu computador.

Os comandos que eu digitar aqui funcionam no Docker de verdade?

Sim — a sintaxe é a mesma do CLI real (docker run -d -p 8080:80 nginx:alpine aqui é idêntico no seu terminal). O que muda é a saída: aqui ela é simulada; lá, é o Docker Engine de verdade respondendo.

Por que o simulador diz "(simulado)" em algumas respostas?

Para você não confundir: comandos que exigiriam internet ou um sistema real (push, login, pull de verdade, shell interativo) são avisados como simulados em vez de fingir que funcionaram.

Consigo ver o estado atual (imagens/containers) sem rodar comando?

Dentro da caixa, rode docker images, docker ps -a, docker volume ls e docker network ls — é o quarteto que resume o estado da máquina.
