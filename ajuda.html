Obtendo ajuda

O próprio comando docker tem um help completo. Você não precisa decorar nada: quando travar, pergunte ao próprio Docker. Nesta aula a Ana mostra os três jeitos de pedir ajuda — do geral ao específico.

Você vai aprender
  • docker --help: a lista de todos os comandos.
  • docker COMANDO --help: as opções de um comando específico (ex.: docker run --help).
  • Como ler uma página de --help (Usage, Commands, Options).
  • O que acontece com um comando que não existe.
  • Onde fica a documentação oficial online (docs.docker.com).

1. docker --help: todos os comandos

O primeiro lugar para procurar. Ele lista cada subcomando com uma frase do que faz:

Missão: rode docker --help.

$ docker --help
Usage:  docker [OPTIONS] COMMAND

A self-sufficient runtime for containers

Commands:
  run       Create and run a new container from an image
  ps        List containers
  images    List images
  pull      Download an image from a registry
  stop      Stop one or more running containers
  start     Start one or more stopped containers
  restart   Restart one or more containers
  rm        Remove one or more containers
  rmi       Remove one or more images
  logs      Fetch the logs of a container
  exec      Run a command in a running container
  build     Build an image from a Dockerfile
  tag       Create a tag TARGET_IMAGE that refers to SOURCE_IMAGE
  network   Manage networks
  volume    Manage volumes
  compose   Docker Compose (v2)
  system    Manage Docker
  inspect   Display detailed information on one or more Docker objects
  stats     Display a live stream of container(s) resource usage statistics
  info      Display system-wide information
  version   Show the Docker version information

Run 'docker COMMAND --help' for more information on a command.

A última linha é a dica de ouro: para detalhar qualquer comando, acrescente --help no fim dele.

2. docker COMANDO --help: as opções de um comando

É aqui que mora o poder: cada subcomando tem dezenas de opções, todas listadas. Veja o docker run --help (resumido):

$ docker run --help
Usage:  docker run [OPTIONS] IMAGE [COMMAND] [ARG...]

Create and run a new container from an image

Options:
      --name string         Assign a name to the container
  -d, --detach              Run container in background and print container ID
  -p, --publish list        Publish a container's port(s) to the host
  -e, --env list            Set environment variables
  -v, --volume list         Bind mount a volume
  -i, --interactive         Keep STDIN open even if not attached
  -t, --tty                 Allocate a pseudo-TTY
      --rm                  Automatically remove the container when it exits
      --restart string      Restart policy (no, always, on-failure, unless-stopped)
      --network string      Connect a container to a network
  …

Anatomia de uma página de --help

Usage: docker run [OPTIONS] IMAGE [COMMAND] [ARG...]
A forma geral do comando: o que é obrigatório (IMAGE) e o que é opcional (entre []).
Commands:
Nos helps de grupos (como o docker --help), a lista de subcomandos.
Options:
Todas as flags. Repare no padrão: a forma curta (-d), a longa (--detach) e o que cada uma recebe (list, string…).
list
Significa que a opção pode ser repetida: -p 80:80 -p 443:443, -e A=1 -e B=2.

3. Comando errado: o próprio erro ajuda

Digitou um comando que não existe? O Docker responde dizendo isso e apontando para o --help:

Missão: digite um comando que não existe (docker abracadabra) e veja a resposta.

$ docker abracadabra
docker: 'abracadabra' is not a docker command.
See 'docker --help'.

Erros assim são comuns quando a gente erra o nome do subcomando (ex.: docker container ls em vez de docker ps — nas versões novas, docker container ls ainda funciona como apelido, mas o padrão é o comando curto).

Erros de digitação não quebram nada

O Docker valida o comando antes de tocar em qualquer container. Se ele disse 'x' is not a docker command, pode ter certeza de que nada aconteceu na sua máquina.

4. A documentação oficial online

O --help do terminal é rápido, mas a referência completa e comentada está na web:

  • docs.docker.com — a documentação oficial: guias, referência de cada comando (docker run tem uma página só com todas as opções), Dockerfile, Compose.
  • Cada imagem oficial no Docker Hub (hub.docker.com) traz a sua página com as variáveis de ambiente e portas que ela aceita — ex.: hub.docker.com/_/postgres.
  • Este guia tem a sua própria cola rápida: Todos os comandos docker e Flags comuns do docker run.

Fluxo recomendado quando travar

  1. Leia a mensagem de erro até o fim — o Docker quase sempre diz o que faltou.
  2. Rode docker COMANDO --help para ver as opções corretas.
  3. Se ainda travar, procure a mensagem de erro na documentação oficial (docs.docker.com) ou na página Erros comuns e soluções deste guia.

Exemplo completo: docker run --help inteiro

Vale a pena ver a página inteira uma vez — é o mapa de tudo o que o run aceita (a aula docker run explica as principais; a cola completa está em flags comuns):

$ docker run --help

Usage:  docker run [OPTIONS] IMAGE [COMMAND] [ARG...]

Create and run a new container from an image

Aliases:
  run, create, start  (create+start é o que o run faz junto)

Options:
      --add-host list             Add a custom host-to-IP mapping (host:ip)
  -a, --attach list               Attach to STDIN, STDOUT or STDERR
      --blkio-weight uint16       Block IO (relative weight), between 10 and 1000
      --cpu-shares int            CPU shares (relative weight)
  -d, --detach                    Run container in background and print container ID
      --detach-keys string        Override the key sequence for detaching a container
  -e, --env list                  Set environment variables
      --env-file list             Read in a file of environment variables
      --expose list               Expose a port or a range of ports
      --name string               Assign a name to the container
  -p, --publish list              Publish a container's port(s) to the host
  -P, --publish-all               Publish all exposed ports to random ports
  -i, --interactive               Keep STDIN open even if not attached
  -t, --tty                       Allocate a pseudo-TTY
      --rm                        Automatically remove the container when it exits
      --restart string            Restart policy: no, always, on-failure, unless-stopped
  -v, --volume list               Bind mount a volume
  -w, --workdir string            Working directory inside the container
      --network string            Connect a container to a network
      --memory string             Memory limit (ex.: 512m, 2g)
      --cpus decimal              Number of CPUs (ex.: 1.5)
  …

Não se assuste com tanta opção: no dia a dia você usaumas cinco (-d, --name, -p, -e, -v, --rm). O resto você consulta quando precisar — e agora sabe onde.

Help dos grupos de comandos

Comandos que têm subcomandos (network, volume, system, compose, image, container) também têm o próprio help:

$ docker network --help
Usage:  docker network COMMAND

Manage networks

Commands:
  connect     Connect a container to a network
  create      Create a network
  disconnect  Disconnect a container from a network
  inspect     Display detailed information on one or more networks
  ls          List networks
  prune       Remove all unused networks
  rm          Remove one or more networks

Run 'docker network COMMAND --help' for more information on a command.
$ docker volume --help
Usage:  docker volume COMMAND

Manage volumes

Commands:
  create      Create a volume
  inspect     Display detailed information on one or more volumes
  ls          List volumes
  prune       Remove all unused local volumes
  rm          Remove one or more volumes

Diferença entre --help, -h e "help"

Você digitaO que acontece
docker --helpLista geral de comandos (o padrão recomendado)
docker run --helpOpções do subcomando run
docker run -hO mesmo que --help (forma curta, aceita na maioria dos comandos)
docker network ls --helpOpções do sub-subcomando ls (sim, dá para descer nível)
Macete de memória: na dúvida, termine o comando com --help. Se você lembra o nome do comando, o próprio Docker te conta o resto.

Atalhos de memória muscular

SituaçãoO que digitar
"Quais comandos existem?"docker --help
"Quais opções o run tem?"docker run --help (ou -h)
"Cadê a doc disso?"docs.docker.com → Reference → CLI → o comando
"Qual versão eu tenho?"docker --version (rápido) ou docker version (cliente + servidor)
"Tem alias/apelido?"Sim: docker container ls = docker ps; docker image ls = docker images; docker container rm = docker rm

Ajuda também existe fora do terminal

  • docs.docker.com — a referência oficial completa (cada comando com exemplos).
  • hub.docker.com — a página de cada imagem explica as variáveis e portas dela.
  • Este guia — cola de todos os comandos, flags do run, erros comuns, glossário.
  • Comunidade: Stack Overflow, Reddit r/docker, Discord oficial — procure a mensagem de erro exata entre aspas.

Resumo

  • docker --help lista todos os comandos; docker COMANDO --help detalha as opções de um comando (é a última linha do help geral que manda fazer isso).
  • Anatomia do help: Usage: mostra a sintaxe; Options: lista as flags (curta, longa, e se aceita valor / pode repetir — list).
  • Comando inexistente → 'x' is not a docker command. See 'docker --help' — e nada acontece com seus containers.
  • Documentação oficial: docs.docker.com; por imagem: a página dela no Docker Hub. Neste guia: cola de comandos e erros comuns.
