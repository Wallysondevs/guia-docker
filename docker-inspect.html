docker inspect — o Raio-X dos objetos

Todo objeto do Docker — container, imagem, volume, rede — tem um JSON gigante guardado no daemon com todos os seus detalhes. O docker inspect imprime esse JSON na tela. Ele é chato de ler inteiro, mas é a base para consultar qualquer coisa por script: com --format você extrai só o campo que precisa.

Você vai aprender
  • Ler a saída JSON do docker inspect (array de objetos, campos principais).
  • Usar --format com templates Go para extrair só um campo: {{.State.Status}}, {{.NetworkSettings.IPAddress}}.
  • {{range}} para percorrer listas (ex.: .Mounts) e o que é <no value>.
  • Inspecionar não só containers, mas também imagens, volumes e redes (--type).
  • Casos práticos: pegar IP num script, listar status de todos os containers com docker ps -q | xargs docker inspect.

Cada objeto vira um elemento de um array JSON (os colchetes [ ] no começo e no fim). É muita coisa — por isso quase sempre vamos filtrar com --format. Antes, uma visão do mapa:

Seção do JSONO que guarda
Id, Name, CreatedIdentidade do objeto (o Name vem com / na frente: /web)
StateEstado atual: Status (running, exited…), Running, datas, ExitCode
ImageO ID (sha256) da imagem usada
ConfigA configuração desejada: imagem, comando (Cmd), variáveis (Env), portas expostas
HostConfigA configuração do host: restart policy, limites de memória/CPU, binds de volumes

Missão: suba um container com docker run -d --name web nginx:alpine e rode docker inspect web. Você deve ver o campo "Id" no JSON.

Anatomia do comando

docker inspect
mostra os detalhes completos de um ou mais objetos, em JSON (um array).
--format '{{…}}'
filtra a saída com um template Go: cada {{.Campo.Subcampo}} acessa um campo do JSON, com ponto separando os níveis.
--type=container
força o tipo do objeto (container, image, volume, network) — útil quando nomes coincidem.
web
o objeto: nome ou ID (os 12 primeiros caracteres do ID bastam). Dá para passar vários de uma vez.

--format: extrair só o que interessa

Em vez de caçar no JSON gigante, peça só o campo — a sintaxe é {{.Campo.Subcampo}}, com ponto separando os níveis:

$ docker inspect --format '{{.State.Status}}' web
running
$ docker inspect --format '{{.NetworkSettings.IPAddress}}' web
172.17.0.2
$ docker inspect --format '{{.Name}} está {{.State.Status}} desde {{.State.StartedAt}}' web
/web está running desde 2025-11-24T12:00:01.000000000Z
$ docker inspect --format '{{.Config.Image}} | portas: {{.Config.ExposedPorts}}' web
nginx:alpine | portas: map[80/tcp:{}]

Se o campo não existe, o Docker imprime <no value> — sinal de que o nome do campo está errado (ou de que o objeto não tem aquele campo, como .Mounts vazio):

$ docker inspect --format '{{.State.Statusss}}' web
<no value>                                          « errei o nome do campo
$ docker inspect --format '{{.State.Status}}' web
running

Com table no começo, a saída vira uma tabela com cabeçalho (bom para vários objetos):

$ docker inspect --format 'table {{.Name}}\t{{.State.Status}}\t{{.NetworkSettings.IPAddress}}' web
NAME      STATUS     IP
/web      running    172.17.0.2

{{range}}: percorrer listas (ex.: os volumes, um por linha)

O Mounts é uma lista, então um {{.Mounts}} sozinho imprime a lista inteira de uma vez. Para um item por linha, use {{range …}}{{end}} e o {{"\n"}} para quebrar a linha:

$ docker run -d --name banco -v dados-postgres:/var/lib/postgresql/data postgres:16-alpine
$ docker inspect --format '{{range .Mounts}}{{.Source}} → {{.Destination}} ({{.Mode}}){{"\n"}}{{end}}' banco
/var/lib/docker/volumes/dados-postgres/_data → /var/lib/postgresql/data (rw)

Dentro do range, o ponto vira o item atual: {{.Source}}, {{.Destination}}, {{.Mode}} (rw = leitura e escrita, ro = só leitura).

Vale para imagem, volume e rede também

O inspect funciona com qualquer tipo de objeto — indique o tipo com --type (ou deixe o Docker descobrir pelo nome):

$ docker inspect --type=image --format 'SO: {{.Os}}/{{.Architecture}}, tamanho: {{.Size}} bytes' nginx:alpine
SO: linux/amd64, tamanho: 50462720 bytes
$ docker inspect --type=volume --format 'driver: {{.Driver}}, criado em: {{.CreatedAt}}' dados-postgres
driver: local, criado em: 2025-11-20T09:12:00Z
$ docker inspect --type=network --format '{{.Name}}: driver {{.Driver}}, escopo {{.Scope}}' bridge
bridge: driver bridge, escopo local

Dá para inspecionar vários objetos de uma vez — o resultado é um array com todos:

$ docker inspect --format '{{.Name}} → {{.State.Status}}' web banco
/web → running
/banco → exited

Missão: o inspect também funciona em imagens: rode docker inspect nginx:alpine e veja o campo "Id" do JSON da imagem.

Exemplo prático 1: pegar o IP num script

$ IP=$(docker inspect --format '{{.NetworkSettings.IPAddress}}' web)
$ echo "o container web está no IP $IP"
o container web está no IP 172.17.0.2
$ curl -s "http://$IP/" | head -1
<!DOCTYPE html>

O $( … ) guarda a saída do comando numa variável do shell — a forma clássica de usar o inspect dentro de scripts.

Exemplo prático 2: status de TODOS os containers de uma vez

Combine docker ps -q (lista só os IDs) com xargs (roda um comando para cada linha):

$ docker ps -aq | xargs docker inspect --format 'table {{.Name}}\t{{.State.Status}}\t{{.State.ExitCode}}'
NAME                STATUS      EXIT CODE
/web                running     0
/banco              exited      137
/cache              running     0

Útil para um diagnóstico rápido: quem está rodando, quem morreu e com que código de saída (137 = morto pelo OOM killer — aula docker stats e Limites de CPU e memória).

JSON bonito: jq

Se tiver o jq instalado, dá para reformatar e filtrar o JSON direto:

$ docker inspect web | jq '.[0].NetworkSettings.Ports'
{
  "80/tcp": [
    {
      "HostIp": "0.0.0.0",
      "HostPort": "8080"
    }
  ]
}
$ docker inspect --format '{{json .State}}' web | jq .
{
  "Status": "running",
  "Running": true,
  "ExitCode": 0
}

O {{json .Campo}} converte o campo para JSON (bom para passar para o jq); o {{pretty .Campo}} imprime o JSON indentado.

Inspecionando serviços do Compose

Os containers criados pelo docker compose são containers normais — o inspect funciona igual, só muda o nome (projeto-serviço-1):

$ docker inspect --format '{{.Name}} usa {{.Config.Image}} e está {{.State.Status}}' meuapp-web-1
/meuapp-web-1 usa nginx:alpine e está running
$ docker inspect meuapp-banco-1 | jq '.[0].Mounts[0]'
{
  "Type": "volume",
  "Name": "meuapp_dados-db",
  "Source": "/var/lib/docker/volumes/meuapp_dados-db/_data",
  "Destination": "/var/lib/postgresql/data"
}

Erros comuns

$ docker inspect meubanco
Error: No such object: meubanco
Atenção: Error: No such object: meubanco significa nome digitado errado ou objeto já removido (um docker system prune passa por aqui — aula prune). Liste os objetos antes (docker ps -a, docker images, docker volume ls, docker network ls) e tente de novo com o nome ou ID certo.
Nome que existe como imagem E como container: se você tem uma imagem web e um container web, o inspect pode escolher o errado. Nesse caso, use --type=container (ou o ID completo) para não ter dúvida.

Resumo

  • O docker inspect NOME imprime um array JSON com tudo sobre o objeto: Id, State, Config, HostConfig, NetworkSettings, Mounts.
  • --format '{{.Campo.Subcampo}}' usa templates Go (ponto = nível) para extrair só um campo; campo inexistente imprime <no value>.
  • {{range .Lista}}…{{end}} percorre listas (ex.: .Mounts); {{"\n"}} quebra linha; table … faz tabela com cabeçalho.
  • Campos úteis: {{.State.Status}}, {{.State.ExitCode}}, {{.NetworkSettings.IPAddress}}, {{.Config.Image}}, {{.Config.Env}}, {{.HostConfig.RestartPolicy.Name}}, {{.HostConfig.Memory}}.
  • Funciona com --type=image|volume|network também; vários objetos de uma vez viram um array só.
  • Em scripts: IP=$(docker inspect --format '{{.NetworkSettings.IPAddress}}' web) e docker ps -aq | xargs docker inspect --format ….
  • Erro comum: Error: No such object: … — nome errado ou objeto já removido; liste com ps -a/images/volume ls antes.
