Docker Compose — um comando para vários containers

Até aqui cada container foi criado com um docker run na mão. Numa aplicação de verdade raramente existe um container só: existe a página web, a API, o banco de dados, um cache... O Docker Compose é a ferramenta que descreve essa pilha inteira num único arquivo YAML e sobe tudo com um comando só: docker compose up.

Você vai aprender
  • O problema de subir vários docker run na mão — e o que se esquece no caminho.
  • A ideia do arquivo declarativo docker-compose.yml ("estado desejado").
  • docker compose up -d para subir tudo e docker compose down para derrubar.
  • Como ler a saída do up (rede, volumes, containers) e o compose ps.
  • A história: Fig → Compose v1 → Compose v2 (plugin do CLI).
  • Como conferir a instalação com docker compose version e os erros reais mais comuns.

A cena: o projeto da Ana no notebook

A Ana está montando no ana@notebook a minhaloja, uma lojinha online de papelaria: um site feito em Nginx, um banco PostgreSQL com os produtos e um cache Redis para as consultas rápidas. No começo ela foi subindo tudo na mão, um comando por serviço, como aprendeu nas aulas anteriores (docker run, portas, volumes):

$ docker run -d --name banco -e POSTGRES_PASSWORD=segredo -v dados-db:/var/lib/postgresql/data postgres:16-alpine
a1b2c3d4e5f6
$ docker run -d --name cache redis:7-alpine
b2c3d4e5f6a1
$ docker run -d --name web -p 8080:80 --link banco --link cache nginx:alpine   « e a rede? e a ordem de subida?
c3d4e5f6a1b2

Funcionou. Mas olhe para esse caderno de comandos e pense no que acontece na prática:

  • A ordem importa: se o banco subir depois da aplicação, a aplicação quebra na inicialização. O --link aqui é um improviso — o jeito certo é uma rede (aula Redes no Docker).
  • É fácil esquecer uma flag: trocou a senha do banco num comando e esqueceu no outro? pronto, dois bancos diferentes.
  • Derrubar tudo depois vira docker stop e docker rm um por um — e se esquecer um, ele fica lá ocupando porta e memória.
  • Passar para outra pessoa é pior: "roda esses 5 comandos na ordem" num README nunca dá certo. A colega da Ana rodou na ordem errada e conclusiu que "Docker não funciona no computador dela".
  • O estado some: se a máquina da Ana desligar, os containers somem com ela; recriar tudo na mão de novo é retrabalho puro.

Dá para automatizar com um script subir.sh... mas script é imperativo: "faça isso, depois aquilo, se der erro pare". Existe um jeito melhor de descrever a aplicação: dizer como ela deve ser, e deixar a ferramenta descobrir o que precisa ser feito. É essa a ideia do Compose.

A ideia: declarativo em vez de imperativo

Pense na diferença entre duas formas de pedir uma pizza. A forma imperativa é dar instruções passo a passo: "pegue a massa, espalhe o molho, coloque o queijo, bote a calabresa, asse por 12 minutos...". A forma declarativa é dizer o resultado desejado: "quero uma pizza de calabresa média" — e deixar o pizzaiolo decidir a ordem das etapas.

O Compose funciona assim. Em vez de uma lista de comandos, você escreve um arquivo declarando o estado desejado do projeto: "quero um serviço web com a imagem nginx:alpine na porta 8080, um serviço banco com PostgreSQL e senha tal, e um volume para os dados". O Compose compara o declarado com o que existe na máquina e faz sozinho o que falta: cria a rede, cria o volume, baixa as imagens, cria os containers na ordem certa e inicia tudo:

# minhaloja/docker-compose.yml — o estado desejado do projeto
services:
  web:                          # um serviço = um container
    image: nginx:alpine
    ports:
      - "8080:80"               # host 8080 -> container 80
    depends_on:
      - banco

  banco:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: segredo
    volumes:
      - dados-db:/var/lib/postgresql/data   # volume nomeado: os dados persistem

  cache:
    image: redis:7-alpine

volumes:                        # declara os volumes nomeados usados acima
  dados-db:

Com esse arquivo na pasta ~/minhaloja, subir a aplicação inteira vira uma linha só:

$ docker compose up -d
[+] Running 5/5
 ✔ Network minhaloja_default   Created                                  0.0s
 ✔ Volume minhaloja_dados-db   Created                                  0.0s
 ✔ Container minhaloja-banco-1 Started                                  0.6s
 ✔ Container minhaloja-cache-1 Started                                  0.5s
 ✔ Container minhaloja-web-1   Started                                  0.5s
docker
o CLI que você já conhece.
compose
o plugin do Compose v2 — com espaço, não com hífen.
up
"suba tudo" que está declarado no arquivo YAML: cria rede, volumes e containers, e inicia.
-d
detach: roda em segundo plano e devolve o terminal na hora (sem ele, o terminal fica preso mostrando os logs de todos os serviços — útil para debugar).

Repare nos nomes: tudo ganhou o prefixo minhaloja-, que é o nome do projeto — por padrão, o nome da pasta onde está o docker-compose.yml. Foi o Compose quem criou a rede minhaloja_default e o volume minhaloja_dados-db, e quem ligou os três containers nessa rede, sem que a Ana pedisse nada disso explicitamente.

down, ps e logs: o ciclo do dia a dia

Quando a Ana termina de trabalhar, ela derruba o projeto inteiro com um comando — containers e rede somem, mas o volume com os dados do banco fica guardado:

$ docker compose down
[+] Running 4/4
 ✔ Container minhaloja-web-1    Removed                                  0.2s
 ✔ Container minhaloja-cache-1  Removed                                  0.1s
 ✔ Container minhaloja-banco-1  Removed                                  0.1s
 ✔ Network minhaloja_default   Removed                                  0.1s

No dia seguinte, um docker compose up -d de novo recria tudo e o banco continua com os mesmos dados. E para espiar o projeto sem sair do terminal:

$ docker compose ps
NAME               IMAGE              STATUS          PORTS
minhaloja-web-1    nginx:alpine       Up 10 seconds   0.0.0.0:8080->80/tcp
minhaloja-banco-1  postgres:16-alpine Up 10 seconds   5432/tcp
minhaloja-cache-1  redis:7-alpine     Up 10 seconds   6379/tcp
$ docker compose logs banco      « só os logs do serviço "banco"
minhaloja-banco-1  | database system is ready to accept connections

Esses quatro comandos — up -d, ps, logs, down — são o ciclo de vida de 90% dos projetos Compose. A aula docker compose up e down detalha cada um.

A história: Fig, Compose v1 e Compose v2

O Compose não nasceu dentro da Docker. Em 2013, a empresa Fig (de Aneesh Chopra e outros fundadores) criou uma ferramenta de orquestração para desenvolvimento local que funcionava exatamente assim: um arquivo YAML descrevendo os serviços e um comando para subir tudo. A Docker gostou da ideia, comprou o projeto e em 2014 lançou o Docker Compose v1 — escrito em Python, instalado à parte, com o comando docker-compose (com hífen).

Em 2021 a Docker reescreveu tudo em Go e transformou o Compose no Compose v2: um plugin do próprio CLI, com o comando docker compose (com espaço). O v1 foi descontinuado em julho de 2023 e hoje não recebe mais correções. Se você digita docker compose, está usando o v2.

Compose v1 (antigo)Compose v2 (atual)
Comandodocker-compose up (hífen)docker compose up (espaço)
LinguagemPython (pacote docker-compose)Go (binário único, mais rápido)
Instalaçãopacote separado via pip/aptplugin do CLI — já vem no Docker Desktop; no Linux, pacote docker-compose-plugin
Statusdescontinuado (fim do suporte em jul/2023)o padrão hoje (ex.: v2.29.7)

Conferindo a instalação

O jeito certo de saber se a máquina da Ana tem o Compose v2 é perguntar a versão:

$ docker --version
Docker version 27.3.1, build 5bcedbc
$ docker compose version
Docker Compose version v2.29.7

Se o primeiro comando funcionar mas o segundo não, o plugin do Compose não está instalado:

Erro real quando o plugin v2 não está instalado: 
$ docker compose version
docker: 'compose' is not a docker command.
See 'docker --help'
No Docker Desktop (Mac/Windows) o plugin já vem pronto. No Linux, instale o pacote docker-compose-plugin (Debian/Ubuntu) ou docker-compose-v2 (Fedora), seguindo a aula Instalar o Docker. Depois da instalação, o comando certo é com espaço: docker compose ....
Cuidado com o comando antigo, com hífen: se na sua máquina existe docker-compose (v1, em Python), ele pode estar desatualizado ou nem existir mais: 
$ docker-compose version
docker-compose: command not found     « ou, pior, uma versão 1.x antiga
Use sempre docker compose (espaço). Dica de ouro: se o seu teclado.autocomplete sugerir hífen, desconfie.

Missão: explore o comando no simulador: rode docker compose --help e encontre na lista a linha do up ("Create and start containers").

Missão: confirme a versão no simulador: rode docker compose version e veja a linha Docker Compose version v2.29.7.

Erros reais do primeiro contato

Rodou o comando na pasta errada: 
$ docker compose up -d
no configuration file provided: not found
O Compose procura o docker-compose.yml na pasta atual. A Ana rodou de ~ em vez de ~/minhaloja. Solução: cd ~/minhaloja ou aponte o arquivo com -f: docker compose -f ~/minhaloja/docker-compose.yml up -d.
O daemon do Docker não está no ar (ou sem permissão): 
$ docker compose up -d
Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?
Ou, em máquinas onde o socket é restrito a um grupo: 
permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock
Solução: inicie o serviço (sudo systemctl start docker) e coloque seu usuário no grupo docker (sudo usermod -aG docker $USER — depois é preciso sair e entrar de novo na sessão). Veja Instalar o Docker e Erros Comuns e Soluções.

Resumo

  • Aplicações de verdade têm vários containers; subir tudo com docker run na mão dá trabalho e esquece fácil (rede, ordem, variáveis, derrubada).
  • O Compose é declarativo: o docker-compose.yml descreve o estado desejado (serviços, imagens, portas, volumes) e o comando descobre o que falta fazer.
  • docker compose up -d cria e inicia rede + volumes + containers; down para e remove containers e a rede (volumes ficam).
  • O nome do projeto vem da pasta (prefixo dos containers: minhaloja-web-1); ps e logs mostram só o projeto.
  • Compose v1 (docker-compose, hífen, Python) está descontinuado; use o v2 (docker compose, espaço, plugin Go) e confirme com docker compose version.
  • Erros comuns: rodar fora da pasta do projeto (no configuration file provided: not found) e daemon parado/sem permissão no socket.
