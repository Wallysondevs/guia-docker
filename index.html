Experimente agora

A caixa abaixo é um terminal Docker simulado: uma máquina fictícia chamada notebook, com a usuária ana, com imagens e containers de mentira. Nada do que você digitar mexe no seu computador. Clique na janela escura, digite docker images e aperte Enter.

Missão: digite docker images e aperte Enter para ver as imagens que a Ana já tem. Depois experimente docker run hello-world e docker ps -a.

O que aconteceu: você rodou o comando docker images, que lista as imagens guardadas na máquina. Uma imagem é como a "receita" de um container — o sistema de arquivos pronto, com tudo instalado. A máquina da Ana já veio com algumas: hello-world, nginx:alpine, node:22-alpine, postgres:16-alpine, redis:7-alpine e python:3.12-slim.

$ docker images
REPOSITORY   TAG          IMAGE ID       CREATED         SIZE
nginx        alpine       b2c3d4e5f6a1   5 days ago      48.2MB
node         22-alpine    c3d4e5f6a1b2   1 week ago      189MB
postgres     16-alpine    d4e5f6a1b2c3   3 days ago      245MB
redis        7-alpine     e5f6a1b2c3d4   1 week ago      42.8MB
python       3.12-slim    f6a1b2c3d4e5   4 days ago      132MB
hello-world  latest       a1b2c3d4e5f6   2 weeks ago     18.2kB

Cada linha é uma imagem: o nome (REPOSITORY), a versão (TAG), o identificador único (IMAGE ID), a idade e o tamanho em disco. A máquina da Ana é só um exemplo — no seu computador, depois de instalar o Docker, a lista começa vazia e vai enchendo conforme você baixa imagens com docker pull.

Uma sessão completa em cinco comandos

Para ter uma ideia de como é o dia a dia, olha a sessão abaixo — é exatamente o que a Ana faria no notebook dela para testar se o Docker está funcionando e ver um site no ar:

$ docker --version
Docker version 27.3.1, build ce12f7b
$ docker run hello-world

Hello from Docker!
This message shows that your installation appears to be working correctly.
…
$ docker run -d -p 8080:80 --name meu-site nginx:alpine
f3a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5
$ docker ps
CONTAINER ID   IMAGE          STATUS         PORTS                  NAMES
f3a1b2c3d4e5   nginx:alpine   Up 5 seconds   0.0.0.0:8080->80/tcp   meu-site
$ docker stop meu-site
meu-site
$ docker rm meu-site
meu-site

Em cinco comandos: conferiu a versão, rodou o "olá, mundo", subiu um site na porta 8080, viu o container na lista, parou e removeu. Cada um desses passos tem uma aula própria neste guia — Seu Primeiro Container, docker run, docker ps, docker stop/start e docker rm.

O que é este guia

O Docker é a ferramenta que empacota um programa com tudo o que ele precisa para rodar (bibliotecas, configurações, dependências) numa caixinha chamada container. Essa caixinha roda igual em qualquer máquina — no seu notebook, num servidor na nuvem, no computador do colega. Quem sabe Docker consegue:

  • rodar qualquer programa sem "na minha máquina funciona": docker run;
  • criar suas próprias imagens com um Dockerfile e docker build;
  • subir vários serviços juntos (site + banco + cache) com Docker Compose;
  • isolar projetos, testar versões diferentes e limpar tudo com um comando.

O guia começa do zero absoluto (o que é um container?) e vai até projetos completos com Compose, imagens enxutas (multi-stage) e dicas de produção. A aula O que é Docker e Containers conta a história e a ideia por trás — vale a leitura antes de pular para os comandos.

Para quem é este guia

Para quem está começando em desenvolvimento, ops ou DevOps e quer entender Docker de verdade, não só copiar comandos. Você não precisa saber programar: o guia usa programas prontos (Nginx, Postgres, Redis, Python) para mostrar o Docker funcionando. Se você já programa, vai reconhecer as situations do dia a dia — a Ana, nossa personagem, passa por elas em todas as aulas no notebook dela.

Como as aulas funcionam

Nenhum comando aparece "seco". Toda aula segue o mesmo caminho:

  1. A ideia primeiro. Antes do comando, você entende o problema que ele resolve, com um exemplo do dia a dia.
  2. Anatomia do comando. Cada pedaço é explicado: o comando, as opções (-d, -p, -v…) e os argumentos.
  3. Terminal com a resposta. Você vê exatamente o que aparece na tela. Toda saída foi conferida no Docker Engine real.
  4. Várias formas de fazer. Quase sempre há mais de um caminho, e uma tabela "Qual usar?" mostra quando escolher cada um.
  5. Quando não funciona. As mensagens de erro reais, por que acontecem e como resolver.
  6. Experimente. Missões no terminal simulado, com verificação na hora.

Exemplo: a anatomia do docker run

Vamos subir um site estático com Nginx numa porta específica:

docker
O programa (o cliente Docker, que fala com o daemon).
run
O subcomando: "crie e inicie um container novo".
-d
Opção detach: roda em segundo plano e devolve o terminal.
-p 8080:80
Opção publish: publica a porta 80 do container na porta 8080 da sua máquina.
--name meu-site
Dá um nome fácil ao container, em vez do nome aleatório.
nginx:alpine
A imagem que vai virar o container (a "receita").
$ docker run -d -p 8080:80 --name meu-site nginx:alpine
f3a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5
$ docker ps
CONTAINER ID   IMAGE          COMMAND                  CREATED          STATUS          PORTS                  NAMES
f3a1b2c3d4e5   nginx:alpine   "/docker-entrypoint.…"   10 seconds ago   Up 10 seconds   0.0.0.0:8080->80/tcp   meu-site

Depois é só abrir http://localhost:8080 no navegador. A aula docker run: anatomia do comando detalha cada opção.

Perguntas que todo mundo faz no começo

Preciso saber programar para aprender Docker?

Não. O guia usa imagens prontas (um site Nginx, um banco Postgres, um interpretador Python) para mostrar cada comando funcionando. Saber o básico de terminal ajuda, mas tudo é explicado passo a passo.

O simulador é igual ao Docker de verdade?

Os comandos e as saídas mostradas nas caixas pre.term foram conferidos no Docker Engine 27 real. O simulador da página imita os principais comandos para você pratiquer sem medo de quebrar nada — a aula Terminal Simulado lista exatamente o que ele sabe e o que não sabe.

Docker é de graça?

O Docker Engine (o que roda os containers) é gratuito e open source. O Docker Desktop (app para macOS/Windows) também é gratuito para uso pessoal, education e pequenas empresas. Publicar imagens no Docker Hub tem plano gratuito com limites. Para aprender, não gasta nada.

Docker funciona no Windows?

Sim. No Windows 10/11 você instala o Docker Desktop com WSL2 (o subsistema Linux do Windows) — a aula Instalar o Docker mostra o passo a passo. No servidor, o mais comum é Linux puro com o Docker Engine.

E máquina virtual, é a mesma coisa?

Não. Máquina virtual simula um computador inteiro (com sistema operacional próprio, pesado e lento para ligar). Container compartilha o sistema do hospedeiro e isola só o processo — liga em segundos e pesa megabytes. A aula O que é Docker e Containers compara os dois lado a lado.

Quanto tempo até eu usar Docker no trabalho?

Com o Nível 1 (umas 2–3 horas de estudo) você já roda banco de dados, sites e APIs locais com containers no mesmo dia. O Nível 2 (Dockerfile + Compose) é o que times usam para desenvolver junto. O resto é aprofundamento.
