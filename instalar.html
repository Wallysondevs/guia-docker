Instalar o Docker

A forma oficial e mais simples de instalar em qualquer sistema é o Docker Desktop (macOS, Windows e até Linux). Em servidores Linux, o recomendado é instalar só o Docker Engine pelo repositório oficial — é mais leve, sem interface gráfica. Esta aula mostra os dois caminhos, passo a passo, e como conferir se deu certo.

Você vai aprender
  • Instalar no Ubuntu/Debian, Arch, Fedora (Engine puro, via repositório oficial).
  • Instalar no macOS e Windows (Docker Desktop + WSL2).
  • O que é cada pacote instalado (docker-ce, containerd.io, buildx, compose-plugin…).
  • Verificar a instalação: docker --version e docker run hello-world.
  • O pós-instalação no Linux: grupo docker e o erro permission denied.
  • O erro Cannot connect to the Docker daemon (daemon parado) e como ligar o serviço.

Antes de começar: Engine ou Desktop?

Há duas formas de ter o Docker na máquina. Pense assim: o Docker Engine é o motor puro (só linha de comando, ideal para servidores e para o WSL2 no Windows). O Docker Desktop é o motor + um pacote com interface gráfica, atualizações automáticas e integração fácil — ideal para notebook (macOS/Windows) de desenvolvimento.

Docker Engine puroDocker Desktop
Onde usarServidores Linux, WSL2Notebooks macOS/Windows (e Linux também)
Interface gráficaNão tem (só terminal)Tem (Dashboard com containers, imagens, volumes)
PesoLeve (~100MB)Mais pesado (VM Linux interna no macOS/Windows)
InstalaçãoRepositório oficial (abaixo)Baixar o instalador em docker.com
Grátis?Sim, 100% open sourceGrátis para uso pessoal, education e pequenas empresas

Nesta aula: Linux → Engine puro (passo a passo oficial); macOS/Windows → Docker Desktop.

Linux (Ubuntu / Debian) — Docker Engine

A Ana usa Ubuntu no notebook dela. A instalação oficial adiciona o repositório da própria Docker ao apt (para receber atualizações automáticas) e instala cinco pacotes. Cada comando abaixo é explicado depois:

$ sudo apt update
$ sudo apt install ca-certificates curl
$ sudo install -m 0755 -d /etc/apt/keyrings
$ sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
$ sudo chmod a+r /etc/apt/keyrings/docker.asc
$ echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
$ sudo apt update
$ sudo apt install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
ca-certificates curl
Ferramentas para baixar arquivos com HTTPS e verificar certificados — o apt precisa delas para falar com o repositório da Docker com segurança.
/etc/apt/keyrings/docker.asc
A chave pública da Docker, baixada do site oficial. Ela serve para o apt conferir que os pacotes que você baixa foram assinados pela Docker (e não por um impostor).
sources.list.d/docker.list
O endereço do repositório oficial, gravado na configuração do apt. O $VERSION_CODENAME descobre sozinho se é noble, jammy etc.
docker-ce
O Engine em si ("Community Edition"): o daemon dockerd e a CLI. É o coração da instalação.
docker-ce-cli
O comando docker (em versões novas já vem junto com o docker-ce, mas o pacote garante).
containerd.io
O runtime de containers que o Docker usa por baixo (o dockerd conversa com ele).
docker-buildx-plugin
O plugin docker buildx — o construtor de imagens moderno (builds multi-plataforma, cache remoto).
docker-compose-plugin
O plugin docker compose (v2) — para subir vários containers com um arquivo YAML (nível 2 do guia).

Depois de instalar, ligue o serviço e faça ele iniciar sozinho no boot:

$ sudo systemctl enable --now docker
$ sudo systemctl status docker    « deve aparecer "active (running)"

Linux (Arch)

$ sudo pacman -S docker docker-compose
$ sudo systemctl enable --now docker

O pacote docker do repositório oficial do Arch já traz o Engine + CLI, e docker-compose é o plugin v2.

Linux (Fedora)

$ sudo dnf -y install dnf-plugins-core
$ sudo dnf config-manager --add-repo https://download.docker.com/linux/fedora/docker-ce.repo
$ sudo dnf install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
$ sudo systemctl enable --now docker

Outras distribuições

Qualquer distro Linux serve (o Docker é só um serviço que fala com o kernel). A forma genérica está em docs.docker.com/engine/install — escolha a sua distro na lista. Se a sua não estiver lá, dá para usar o script de conveniência: curl -fsSL https://get.docker.com | sudo sh (prático para testes e VMs; em produção, prefira o repositório oficial passo a passo).

macOS e Windows — Docker Desktop

Baixe o instalador em docker.com/products/docker-desktop, instale e abra o app. Pronto: o docker já funciona no terminal.

No Windows, é preciso ter o WSL2 ativo (o subsistema Linux do Windows) — o instalador do Docker Desktop cuida disso automaticamente na primeira execução; se pedir, rode wsl --install no PowerShell como administrador e reinicie.

No macOS, o Desktop roda o Engine dentro de uma VM Linux interna (leve) — por isso o comando docker funciona igual no Terminal do Mac.

Licença do Docker Desktop

O Docker Desktop é gratuito para uso pessoal, estudantil, emONGs e empresas pequenas (menos de 250 funcionários ou US$10M de receita). Empresa maior precisa de licença paga — nesse caso, no servidor Linux dá para usar só o Engine gratuito. Para aprender e usar em casa, não paga nada.

Verificar a instalação

Fechou o terminal e abriu de novo (ou reiniciou)? Rode os dois comandos abaixo. O primeiro diz a versão; o segundo é o teste de fumaça oficial:

$ docker --version
Docker version 27.3.1, build ce12f7b
$ docker run hello-world

Hello from Docker!
This message shows that your installation appears to be working correctly.

To generate this message, Docker took the following steps:
 1. The Docker client contacted the Docker daemon.
 2. The Docker daemon pulled the "hello-world" image from the Docker Hub.
 3. The Docker daemon created a new container from that image.
 4. The Docker daemon streamed that output to the Docker client.

No simulador: rode docker --version para ver a versão que o guia imita.

Se o docker --version deu certo mas o hello-world não, o problema quase sempre é o daemon parado ou permissão — as duas seções abaixo.

Pós-instalação no Linux: o grupo docker

Em servidor Linux, depois de instalar, o seu usuário ainda não pode falar com o daemon. Teste:

$ docker ps
permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock: Get "http://%2Fvar%2Frun%2Fdocker.sock/v1.27/containers/json": dial unix /var/run/docker.sock: connect: permission denied

A correção é colocar seu usuário no grupo docker (esse grupo pode criar containers, ou seja, tem poder de root na máquina):

$ sudo usermod -aG docker $USER
$ newgrp docker          « ou: saia e entre de novo na sessão (logout/login)
$ docker ps
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES
Segurança: o grupo docker dá poderes de root (quem manda no grupo docker manda no sistema, porque consegue montar a raiz do host dentro de um container). Em produção, prefira rodar o Docker como serviço e usar sudo só quando necessário, ou configure o rootless mode (Docker sem root, com socket do usuário).

Erro comum: "Cannot connect to the Docker daemon"

Esse erro quer dizer uma coisa só: a CLI está instalada, mas o serviço dockerd não está rodando (ou você não tem permissão no socket — caso anterior).

$ docker ps
Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?
$ sudo systemctl start docker      « liga agora
$ sudo systemctl enable docker     « liga sozinho no boot
$ sudo systemctl status docker
● docker.service - Docker Application Container Engine
   Active: active (running)

No Docker Desktop (Mac/Windows), o equivalente é abrir o aplicativo — enquanto ele não estiver rodando (baleia na barra de menus), o comando dá esse erro.

Erros comuns na hora de instalar

"Package 'docker' has no installation candidate" (Ubuntu/Debian)

Você tentou sudo apt install docker (o pacote antigo da distro, que já não existe ou é outra coisa). A instalação correta é pelo repositório oficial, com os comandos desta aula — o pacote certo chama-se docker-ce.

"signature does not match" / erro de chave GPG

A chave em /etc/apt/keyrings/docker.asc está errada ou corrompida (acontece quando se copia o comando errado). Apague o arquivo e refaça o passo do curl exatamente como está acima.

Windows: "WSL2 installation is incomplete"

Rode wsl --install no PowerShell como administrador, reinicie o computador e abra o Docker Desktop de novo. Sem o WSL2 o Desktop não sobe.

Resumo

  • Linux (servidor/WSL2): instale o Docker Engine pelo repositório oficial — pacote docker-ce + docker-ce-cli + containerd.io + plugins buildx e compose; depois sudo systemctl enable --now docker.
  • macOS/Windows: Docker Desktop (no Windows precisa do WSL2; o instalador cuida disso).
  • Teste de fumaça: docker --version e docker run hello-world.
  • permission denied no socket → adicione o usuário ao grupo docker (sudo usermod -aG docker $USER + nova sessão). Cuidado: o grupo docker equivale a root.
  • Cannot connect to the Docker daemon → o serviço está parado; ligue com systemctl start docker (ou abra o Docker Desktop).
  • Pacotes: docker-ce = Engine; containerd.io = runtime; docker-buildx-plugin = builds modernos; docker-compose-plugin = Compose v2.
