Erros comuns e soluções

Errar faz parte — e no Docker a boa notícia é que as mensagens de erro são longas, mas sinceras: a causa quase sempre está na última linha. A Ana já colecionou sustos o suficiente para montar esta página: são os 17 erros mais comuns, cada um com a mensagem real (Docker Engine 27.x), a causa e a solução passo a passo. No fim, uma tabela resumo para diagnosticar rápido.

Você vai aprender
  • A ler a mensagem de erro do Docker até o fim — a causa está na última linha.
  • O trio de diagnóstico que resolve quase tudo: docker ps -a, docker logs NOME, docker inspect NOME.
  • Resolver: daemon parado, permissão no socket, porta ocupada, imagem inexistente, nome repetido, remover rodando, permissão em mount, exec em container parado, disco cheio, unhealthy, container que morre na hora, DNS entre containers, variável faltando, rate limit, COPY failed e "docker não encontrado".

O ritual de diagnóstico (use antes de qualquer erro)

  1. docker ps -a — quem está rodando? Quem está parado com Exited (N)? O número entre parênteses é o código de saída do processo (0 = saiu bem; 1, 137… = erro ou morte por sinal).
  2. docker logs NOME — o que o app imprimiu antes de morrer? Quase todo container que "sai na hora" deixou a pista aqui.
  3. docker inspect NOME — detalhes em JSON: rede, portas publicadas, volumes, imagem, comando, variáveis de ambiente.
  4. docker system df — se o erro envolve disco/espaço, esse comando mostra quem está ocupando.

1. Não conecta no daemon

Erro real: docker: Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?

Causa: o servidor do Docker (dockerd) não está rodando — ou está, mas seu usuário não tem permissão para falar com o socket.

$ sudo systemctl start docker     « inicia o serviço agora
$ sudo systemctl enable docker    « para iniciar junto com o sistema
$ docker info                     « confirma que está no ar
Server:
  Containers: 0
  Images:     6
  Server Version: 27.3.1

No Docker Desktop (Mac/Windows), basta abrir o aplicativo — se ele estiver aberto e o erro persiste, reinicie o app.

2. Permissão negada no socket

Erro real: permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock

Causa: seu usuário não está no grupo docker, que é o dono do socket. A alternativa preguiçosa é rodar tudo com sudo — funciona, mas acostuma mal e quebra scripts.

$ sudo usermod -aG docker $USER     « adiciona seu usuário ao grupo
$ newgrp docker                     « aplica na sessão atual (ou faça logout/login)
$ docker ps                         « agora funciona sem sudo

3. Porta já está em uso

Erro real: docker: Error response from daemon: driver failed programming external connectivity on endpoint meu-site (a1b2c3d4e5f6…): Bind for 0.0.0.0:8080 failed: port is already allocated.

Causa: outro processo — outro container ou um programa do host — já está usando a porta 8080 da sua máquina.

$ docker ps                                   « procure quem publicó a 8080
… 0.0.0.0:8080->80/tcp
$ sudo ss -ltnp | grep 8080                   « ou veja no host quem escuta a porta
$ docker run -d -p 8081:80 --name meu-site nginx:alpine   « use outra porta do host
$ docker run -d -p 8080:80 --name meu-site nginx:alpine   « agora foi

Lembre: no -p HOST:CONTAINER, é o lado HOST que precisa estar livre.

4. Imagem não existe / pull negado

Erro real: Unable to find image 'meuapp:1.0' locally seguido de docker: pull access denied for meuapp, repository does not exist or may require 'docker login'.

Causa: a imagem não está no computador e o Docker tentou baixar do Hub (o run faz pull automático) — mas o nome/tag está errado, o repositório é privado, ou não existe.

$ docker images                       « veja o que você tem local
$ docker pull nginx:alpine            « baixa a imagem certa
$ docker run -d -p 8080:80 nginx:alpine
$ docker login                        « para repositórios privados, antes do pull/run

Se rodou docker run api:latest antes do docker build -t api ., dá esse mesmo erro — build primeiro, run depois.

5. Nome de container repetido

Erro real: docker: Error response from daemon: Conflict. The container name "/meu-site" is already in use by container "a1b2c3d4e5f6…". You have to remove (or rename) that container to be able to reuse that name.

Causa: nomes são únicos — já existe um container (mesmo parado) com esse --name.

$ docker ps -a                        « procure o dono do nome
$ docker rm meu-site                  « apaga o container antigo (parado)
$ docker run -d --name meu-site nginx:alpine   « agora o nome está livre
# ou escolha outro nome:
$ docker run -d --name meu-site-2 nginx:alpine

6. Remover container que está rodando

Erro real: Error response from daemon: cannot remove container "meu-site": container is running: stop the container before removing or force remove

Causa: docker rm sem -f só apaga container parado. A própria mensagem entrega a solução.

$ docker stop meu-site
meu-site
$ docker rm meu-site
meu-site
# ou, se tiver certeza absoluta (banco de dados pode corromper!):
$ docker rm -f meu-site

7. Permission denied ao montar pasta

Erro real (Linux): docker: Error response from daemon: failed to create shim task: OCI runtime create failed: runc create failed: unable to start container process: error during container init: open /dados/arquivo.txt: permission denied: unknown.
Erro real (Docker Desktop): Mounts denied: The path /home/ana/site is not shared from the host and is not known to Docker.

Causa: três CANDIDATAS comuns: (a) o caminho do host não existe; (b) no Docker Desktop, a pasta não está na lista de "File sharing" (Settings → Resources → File sharing); (c) o usuário dentro do container não tem permissão de ler/escrever na pasta do host.

$ ls -ld /home/ana/site               « confirme que a pasta existe
$ sudo chown -R 1000:1000 /home/ana/site   « ajusta o dono para o UID do usuário do container
$ docker run -d -v /home/ana/site:/app/site:ro --user 1000:1000 nginx:alpine
# no Docker Desktop: vá em Settings > Resources > File sharing e adicione a pasta

8. OCI runtime exec failed (executável não existe)

Erro real: docker: Error response from daemon: OCI runtime exec failed: exec failed: unable to start container process: exec: "bash": executable file not found in $PATH: unknown.

Causa: a imagem não tem aquele executável. Imagens Alpine e distroless não têm bash — só sh. Também acontece com curl em imagens mínimas.

$ docker exec -it meu-site sh        « use sh, não bash
$ docker exec meu-site which curl     « erro se não tiver curl na imagem
# para instalar dentro do container (Alpine):  docker exec meu-site sh -c 'apk add curl'

9. exec em container parado

Erro real: Error response from daemon: Container meu-site is not running

Causa: docker exec só funciona em container rodando. Se o container já saiu, ou você inicia de novo (docker start) ou lê os logs (docker logs) para ver o que aconteceu.

$ docker ps -a                        « viu que está "Exited"?
$ docker start meu-site               « inicia de novo
$ docker exec -it meu-site sh         « agora vai
# se ele sai de novo na hora, veja por quê:
$ docker logs meu-site

10. Container morre na hora (sai com código != 0)

Sintoma: docker run -d … imprime o ID, mas o docker ps -a mostra Exited (1) 2 seconds ago.

Causa: o processo principal do container terminou com erro. A pista está nos logs:

$ docker run -d --name api api:latest
a1b2c3d4e5f6…
$ docker ps -a
CONTAINER ID   IMAGE         STATUS                       NAMES
a1b2c3d4e5f6   api:latest    Exited (1) 3 seconds ago     api
$ docker logs api
node:internal/modules/cjs/loader:1080
  throw err;                     « erro real do Node: módulo não encontrado, porta errada, etc.
…
$ docker run --rm api:latest node -e "console.log('testando')"   « rode outro comando pra debugar

Erros clássicos que fazem isso: porta do app diferente da publicada, listen em 127.0.0.1 (app sobe mas não responde de fora), variável de ambiente obrigatória faltando, arquivo de configuração não encontrado dentro da imagem.

11. Disco cheio

Erro real: docker: Error response from daemon: … write /var/lib/docker/overlay2/…: no space left on device. (também aparece no pull: failed to register layer: … no space left on device)

Causa: imagens, containers parados, volumes e cache de build acumularam e encheram a partição do Docker (ou o disco todo).

$ docker system df                    « veja quanto cada coisa ocupa
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          40        3         12GB      10GB (83%)
Containers      15        2         2GB       1.8GB (90%)
Local Volumes   8         1         30GB      25GB (83%)
Build Cache     120       0         8GB       8GB
$ docker system prune -a --volumes    « limpa containers parados, imagens soltas, redes, cache E volumes não usados
$ df -h                               « se o próprio host estiver cheio, libere espaço fora do Docker

Para o cache de build especificamente: docker builder prune.

12. Healthcheck unhealthy

O sintoma: no docker ps o status aparece como Up 2 minutes (unhealthy), e docker inspect --format '{{.State.Health.Status}}' meu-site devolve unhealthy.

Causa: o comando do HEALTHCHECK está falhando dentro do container — o app pode estar no ar mas o teste está errado (porta errada, ferramenta faltando na imagem — ex.: curl que não existe em Alpine, app ainda inicializando).

$ docker inspect meu-site | grep -A8 '"Health"'   « histórico dos testes e o erro de cada um
$ docker logs meu-site                              « o app está de pé?
$ docker exec meu-site wget -qO- http://localhost:3000/saude   « teste o healthcheck na mão
# imagem mínima sem curl/wget: use outra forma:
# HEALTHCHECK CMD node -e "require('http').get('http://localhost:3000/saude', r => process.exit(r.statusCode===200?0:1))"

Corrija o HEALTHCHECK no Dockerfile (ou o --health-cmd no run) e recrie o container (healthcheck não muda em container existente: docker stop + rm + run de novo).

13. Containers não se acham pelo nome na rede

Erro real: Error: getaddrinfo ENOTFOUND db (Node) ou psycopg2.OperationalError: could not translate host name "db" (Python) ou ping: bad address 'api'.

Causa: o DNS interno do Docker só resolve nomes de containers que estão na mesma rede — e a rede padrão bridge não tem DNS automático (só redes criadas por usuário/Compose têm). Se um dos containers está na bridge padrão e o outro numa rede própria, eles não se enxergam por nome.

$ docker network create appnet
$ docker run -d --name db --network appnet postgres:16-alpine
$ docker run -d --name api --network appnet -e DATABASE_URL=postgresql://postgres:segredo@db:5432/app api:latest
$ docker exec api ping -c1 db
PING db (172.18.0.2): 56 data bytes   « agora resolve!

Com Compose isso não acontece: todos os serviços do mesmo projeto entram na mesma rede automaticamente (a menos que você os separe de propósito).

14. Variável não definida no Compose

Aviso real: WARN: The "POSTGRES_PASSWORD" variable is not set. Defaulting to a blank string. — e o serviço sobe com a variável vazia e quebra depois.

Causa: o YAML usa ${VAR} e ela não existe no arquivo .env nem no ambiente do shell.

$ cat .env                            « confira o arquivo na pasta do projeto
POSTGRES_PASSWORD=segredo
$ docker compose config | grep -i password   « veja como ficou resolvido
$ echo ".env" >> .gitignore           « e nunca commite o .env

15. Rate limit no pull (Docker Hub)

Erro real: toomanyrequests: You have reached your pull rate limit. (ou 429 Too Many Requests)

Causa: o Docker Hub limita pulls anônimos (100 a cada 6h por IP) e o limite estourou — comum em CI e em redes de empresa com NAT.

$ docker login -u ana                « logado, o limite é maior (e ilimitado em planos pagos)
$ docker pull nginx:alpine
# em CI: use o login-action com secrets, ou um mirror/registry próprio

16. COPY failed no build

Erro real: #8 ERROR: failed to solve: failed to compute cache key: failed to calculate checksum of ref …: failed to walk /var/lib/docker/tmp/buildkit-mount…: lstat /app/arquivo.txt: no such file or directory — e a variante mais comum: COPY failed: file not found in build context or excluded by .dockerignore.

Causa: o arquivo não está no contexto de build (a pasta do . no comando) ou foi excluído pelo .dockerignore.

$ ls                       « rode na MESMA pasta do build e veja se o arquivo está lá
$ cat .dockerignore        « o arquivo está nessa lista? tire de lá
$ docker build -t app .    « o contexto é a pasta atual — não a pasta do Dockerfile, se forem diferentes

17. docker: command not found

Erro real: bash: docker: command not found

Causa: o Docker não está instalado ou não está no PATH dessa sessão (comum após instalar sem reiniciar o terminal, ou dentro de um shell estranho).

$ which docker          « nada? não está no PATH
$ sudo systemctl status docker   « instalado mas parado?
$ echo $PATH              « a pasta /usr/bin está aí?
# reinstale pela aula:
# → instalar.html

Pratique o diagnóstico

Missão: rode docker run hello-world (sem --rm) e depois docker ps -a — você vai ver o container parado com status Exited (0), que é exatamente o que aparece quando um container terminou.

Resumo

  • Leia a mensagem até o fim: a última linha quase sempre diz a causa e, às vezes, a própria solução.
  • Diagnóstico padrão: docker ps -a → docker logs NOME → docker inspect NOME → docker system df.
  • Os clássicos: daemon parado, socket sem permissão, porta ocupada, run antes do build, nome repetido, rm em container rodando, Alpine sem bash, disco cheio, healthcheck errado.
  • Container que morre na hora = olhe os logs; containers que não se acham = cheque se estão na mesma rede.
  • Nunca apague volumes às cegas: prune --volumes e compose down -v são irreversíveis.
