docker rm — removendo containers

Container parado ocupa pouco, mas enche a lista do docker ps -a e pode segurar espaço de disco. O docker rm apaga o container de vez — diferente do stop, que só para. Nesta aula a Ana limpa a bagunça de testes dela.

Você vai aprender
  • Remover por nome e por ID curto.
  • Remover vários de uma vez e o -f (forçar mesmo rodando).
  • O erro real de apagar container rodando sem -f.
  • docker container prune: apagar todos os parados de uma vez.
  • O que acontece com os dados do container ao apagar (e por que existem volumes).

A cena: a lista da Ana está cheia de testes

$ docker ps -a
CONTAINER ID   IMAGE          STATUS                      PORTS     NAMES
a1b2c3d4e5f6   nginx:alpine   Up 2 minutes                80/tcp    meu-site
c3d4e5f6a1b2   hello-world    Exited (0) 10 minutes ago           clever_curie-42
7d3a1b9c2e4f   hello-world    Exited (0) 5 minutes ago            boring_torvalds-7

Ela quer apagar os dois hello-world parados e manter o site no ar.

Por nome ou ID

Missão: crie um container parado (docker run --name meu-site hello-world) e remova com docker rm meu-site.

$ docker rm clever_curie-42
clever_curie-42
$ docker rm 7d3a          « ID curto também funciona
boring_torvalds-7
$ docker ps -a
CONTAINER ID   IMAGE          STATUS          PORTS     NAMES
a1b2c3d4e5f6   nginx:alpine   Up 2 minutes    80/tcp    meu-site   « só sobrou o site

O comando imprime o nome do container removido — é a confirmação de que deu certo. Se o nome/ID não existir:

$ docker rm nao-existe
Error: No such container: nao-existe

Apagar vários de uma vez

$ docker rm container1 container2 container3     « vários argumentos
$ docker rm $(docker ps -aq)    « apaga TODOS os containers PARADOS (rodando dá erro sem -f)

-f: forçar mesmo rodando

$ docker rm -f meu-site   « equivalente a stop + rm
meu-site

O -f manda parar na marra (kill) e apaga em seguida. Prático para limpar rápido — mas lembre: os dados da camada gravável vão junto.

Erro comum: apagar container rodando

Missão: suba um container rodando (docker run -d --name meu-site nginx:alpine) e tente apagar sem parar: docker rm meu-site. Veja o erro real.

$ docker run -d --name meu-site nginx:alpine
$ docker rm meu-site
Error response from daemon: cannot remove container "meu-site": container is running: stop the container before removing or force remove

Container rodando não pode ser removido sem -f. O Docker protege você de apagar algo em uso sem querer. Como consertar: docker stop meu-site e depois docker rm meu-site — ou direto docker rm -f meu-site.

docker container prune: limpar todos os parados

Em vez de apagar um por um, o prune remove todos os containers parados de uma vez (os rodando continuam):

$ docker ps -a
… vários Exited…
$ docker container prune
WARNING! This will remove all stopped containers.
Are you sure you want to continue? [y/N] y
Deleted Containers:
clever_curie-42
boring_torvalds-7
Total reclaimed space: 2.5kB
$ docker ps -a
… só o que está rodando (ou vazio)

Existe também o docker system prune, que além dos containers parados apaga imagens dangling, redes não usadas e cache de build — aula docker system prune.

stop × rm: a diferença que salva seus dados

docker stopdocker rm
O container depoisExiste, parado (Exited no ps -a)Não existe mais (sai até do ps -a)
Arquivos gravados dentro deleContinuam lá (dá para dar start e voltar)Somem com a camada gravável
Pode dar start depois?SimNão
Libera espaço?Muito poucoSim (a camada gravável)
Apagar container apaga os dados dele (se não tiver volume)

Se o container gravou arquivos (um banco de dados gravando em /var/lib/postgresql/data, um upload em /app/uploads), esses arquivos estão na camada gravável e somem com o docker rm. A imagem continua (é só a receita), mas os dados vão embora. Para dados que devem sobreviver: monte um volume com -v — aí eles ficam fora do container e o rm não os apaga.

Limpeza geral (quando a máquina encheu)

  1. docker ps -a — veja todos os containers.
  2. docker stop $(docker ps -q) — para os rodando (se quiser manter algum, pare só ele pelo nome).
  3. docker rm $(docker ps -aq) — apaga todos.
  4. docker images — veja as imagens; apague as que não usa com docker rmi (aula).
  5. docker system df — confere quanto espaço sobrou.
  6. Opcional, limpeza total: docker system prune -a (apaga containers parados + imagens sem container + cache; não apaga volumes por padrão).
O que o rm NÃO apaga

O docker rm apaga só o container. A imagem continua (é a receita — docker rmi apaga ela), os volumes continuam (são dados separados — docker volume rm apaga) e as redes continuam. Ou seja: seus dados em volumes estão seguros; o que some é só a "casca" do container.

Apagar container que usa volume: o volume fica

Regra importante: o docker rm apaga o container, mas não apaga os volumes que ele usava. Veja:

$ docker run -d --name banco -v dados-postgres:/var/lib/postgresql/data -e POSTGRES_PASSWORD=x postgres:16-alpine
$ docker rm -f banco
banco
$ docker volume ls
DRIVER    VOLUME NAME
local     dados-postgres     « o volume (e os dados) continuam ✅
$ docker run -d --name banco2 -v dados-postgres:/var/lib/postgresql/data -e POSTGRES_PASSWORD=x postgres:16-alpine
$ docker exec banco2 psql -U postgres -c "SELECT count(*) FROM clientes;"   « dados lá, firmes
 30

Ou seja: rm apaga a "casca"; o volume é o "cofre" e só sai com docker volume rm NOME (cuidado: aí os dados vão de vez).

prune de container × system prune

ComandoApaga o quê
docker container pruneSó containers parados
docker image pruneSó imagens dangling (<none>)
docker volume pruneSó volumes sem container usando (perigoso: dados!)
docker network pruneRedes não usadas
docker system pruneContainers parados + imagens dangling + redes + cache de build (volumes só com -a/--volumes)
docker system prune -aTudo que não está em uso agora, inclusive imagens com tag (cuidado!)

Remover só os que saíram com erro

Útil para limpar a bagunça de testes que falharam:

$ docker rm $(docker ps -a -q --filter "status=exited" --filter "exited=1")
…   « apaga só os containers parados que saíram com código 1 (erro)

O filtro exited=1 pega só os que falharam; sem ele, pega todos os parados.

ID curto: quantos caracteres bastam?

O ID completo tem 64 caracteres, mas o Docker aceita um prefixo único — na prática, 3–4 caracteres já bastam na máquina local:

$ docker ps -a
CONTAINER ID   IMAGE   STATUS   NAMES
f3a1b2c3d4e5…  nginx   Up       meu-site
$ docker stop f3a        « 3 caracteres e já achou
meu-site
$ docker stop f3a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5   « o ID inteiro também funciona
meu-site

Se o prefixo bater em mais de um container, o Docker avisa (Error: ambiguous ID) — aí é só usar mais caracteres.

Resumo

  • docker rm NOME (ou ID curto) apaga o container de vez e imprime o nome como confirmação; vários: docker rm a b c.
  • Container rodando não sai sem -f: erro real cannot remove container "X": container is running: stop the container before removing or force remove.
  • docker rm -f X = stop + rm (mata na marra e apaga). docker rm $(docker ps -aq) apaga todos os parados.
  • docker container prune remove todos os containers parados de uma vez (com confirmação).
  • stop ≠ rm: stop guarda (dá para religar); rm apaga — e junto vão os arquivos da camada gravável (dados importantes = volume).
  • Erro: Error: No such container: X (nome errado ou já apagado).
