Modo interativo (-it)

Às vezes você quer entrar dentro do container e fuçar: abrir um shell, rodar um comando, testar um arquivo. As flags -it fazem isso. E tem um truque importante para sair sem matar o container: Ctrl+P Ctrl+Q.

Você vai aprender
  • O que é cada flag: -i (entrada aberta) e -t (terminal/tty).
  • Rodar um shell dentro de uma imagem: docker run -it alpine sh.
  • Rodar um REPL: docker run -it python:3.12-slim python.
  • Ctrl+P Ctrl+Q: sair sem parar o container (detach).
  • A diferença entre detach, Ctrl+C e exit.
  • docker attach: entrar num container que já está rodando.

-i e -t: as duas metades do "entrar no container"

-i (interactive)
Mantém a entrada (stdin) aberta: o que você digita chega dentro do container. Sem -i, o container não recebe nada do seu teclado.
-t (tty)
Aloca um terminal virtual (pseudo-TTY): você vê o prompt, cores, e teclas como Ctrl+C funcionam direito. Sem -t, a saída vem "crua", sem prompt.
-it junto
As duas coisas: você entra num shell de verdade dentro do container.
ComandoO que acontece
docker run alpine echo oi (sem -it)Imprime "oi" e sai — sem entrada, sem terminal
docker run -i alpine catO cat fica lendo o que você digita (entrada aberta, sem prompt bonito)
docker run -t alpine shAbre o shell, mas a entrada pode não chegar direito (sem -i)
docker run -it alpine shShell de verdade dentro do container: prompt, comandos, cores

Exemplo 1: um shell no Alpine

$ docker run -it --rm alpine sh
/ # ls
bin  dev  etc  home  lib  media  mnt  opt  proc  root  run  sbin  srv  sys  tmp  usr  var
/ # cat /etc/os-release
NAME="Alpine Linux"
ID=alpine
VERSION_ID=3.20.3
/ # echo "estou dentro do container!" > /tmp/teste.txt
/ # cat /tmp/teste.txt
estou dentro do container!
/ # exit        « sai do shell…

O / # é o prompt de dentro do container (raiz do sistema de arquivos dele — repare que é um sistema completo, só que mínimo). O --rm faz o container ser apagado ao sair (bom para testes: não deixa lixo no ps -a).

O arquivo sumiu?

Experimente: rode de novo docker run --rm alpine cat /tmp/teste.txt. Vai dar erro ("No such file"). Por quê? Porque cada docker run cria um container novo, com a camada gravável nova e vazia — o /tmp/teste.txt ficou no container antigo, que o --rm apagou. É a regra de ouro: dados dentro do container somem com ele (aula volumes resolve).

Exemplo 2: o REPL do Python

$ docker run -it --rm python:3.12-slim python
Python 3.12.7 (main, …) [GCC …] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>> 2 + 2
4
>>> print("olá do container")
olá do container
>>> exit()

Você abriu o interpretador Python dentro do container. Dá para importar bibliotecas que a imagem tem, ler arquivos dela, testar código na versão exata que vai rodar em produção.

Sair sem parar o container: Ctrl+P Ctrl+Q

Se você entrou com -it num container que vai continuar rodando (sem --rm), tome cuidado com a saída:

Você fazO que acontece
Ctrl+P Ctrl+QDetach: você sai da tela, mas o container continua rodando em segundo plano ✅
exit (ou Ctrl+D)Encerra o processo principal (o shell). Se ele era o processo do container (PID 1), o container para ❌
Ctrl+CManda SIGINT para o processo dentro do container — se for um shell, ele pode só cancelar a linha; se for um servidor, pode matar ❌
$ docker run -it -d --name meu-shell alpine sh
$ docker ps
… Up 5 seconds   meu-shell     « está rodando em segundo plano
(dentro do shell: Ctrl+P Ctrl+Q para sair sem parar)
$ docker ps                    « depois do detach, continua Up
… Up 1 minute    meu-shell
$ docker exec -it meu-shell sh    « para voltar a entrar depois (próxima aula)
O truque só funciona com -t

O Ctrl+P Ctrl+Q é interpretado pelo Docker quando tem TTY alocado (flag -t). Sem -t, o Ctrl+P vai direto para o programa de dentro. Por isso o par -it anda sempre junto.

Missão: suba um container interativo em segundo plano: docker run -it -d --name meu-shell node:22-alpine sh. Depois rode docker ps e veja o meu-shell como Up 2 minutes.

docker attach: entrar num container que já está rodando

Entra num container que já está rodando (diferente do run -it, que cria um novo):

$ docker attach meu-shell
/ #          « você está dentro do container que já existia
(sair com Ctrl+P Ctrl+Q para não parar ele)
docker run -it …docker attach Xdocker exec -it X sh
Cria container novo?SimNãoNão
Entra em um que já roda?—SimSim (maneira moderna)
Quando usarTestar uma imagem na horaVer a saída ao vivo do processo principalEntrar para fuçar/debugar (recomendado)

Na prática, para entrar num container que já está no ar, o pessoal usa mais o docker exec -it X sh (próxima aula) — ele abre um processo novo dentro do container, e sair dele não mata o container.

Para que usar o -it no dia a dia

Além de "fuçar", o modo interativo serve para várias coisas práticas da Ana:

  • Testar um comando dentro da imagem antes de usar no Dockerfile: docker run -it --rm node:22-alpine sh → dentro, rode npm install, veja se deu certo, ajuste — sem sujar sua máquina.
  • Debugar um container que quebra na inicialização: em vez de node server.js, rode docker run -it --rm meuapp sh e vá testando os comandos um a um até achar o erro.
  • Rodar migrações de banco manualmente: docker run -it --rm --network host meuapp sh -c "npm run migrate".
  • Ver o que tem dentro de uma imagem: docker run -it --rm alpine sh → ls /, cat /etc/os-release, which curl.

Cuidado ao entrar em container de produção

Em produção, entrar num container com -it/exec e rodar comandos pode piorar as coisas (matar processo, apagar arquivo, mudar estado). A regra de ouro: em produção, prefira olhar (logs, stats, inspect) e, se precisar mudar algo, troque a imagem e recrie o container — nunca "conserte na mão" dentro do container, porque a mudança some no próximo deploy.

Copiar arquivos para dentro e para fora: docker cp

O modo interativo não é a única forma de trocar arquivos com um container. O docker cp copia entre sua máquina e o container (rodando ou parado):

$ docker cp meu-arquivo.txt meu-shell:/tmp/     « host → container
$ docker cp meu-shell:/tmp/resultado.txt .      « container → host
$ docker cp meu-shell:/var/log/nginx/access.log ./access.log   « baixa os logs do servidor

Útil quando o container não tem shell (imagens distroless) ou quando você quer um arquivo de dentro sem entrar lá.

Resumo

  • -i = entrada aberta (stdin); -t = terminal (tty). Juntos (-it), você entra num shell dentro do container.
  • Exemplos: docker run -it --rm alpine sh, docker run -it --rm python:3.12-slim python.
  • Sair sem parar: Ctrl+P Ctrl+Q (detach). exit/Ctrl+C podem matar o processo principal e parar o container.
  • --rm no run interativo = container some ao sair (bom para testes).
  • Cada run cria container novo: arquivos gravados num somem com ele (use volumes para persistir).
  • docker attach X entra num container que já está rodando; docker exec -it X sh é a forma moderna de entrar (próxima aula).
