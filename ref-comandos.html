Todos os comandos docker (cola)

Esta é a sua cola de consulta rápida: todos os comandos do Docker CLI separados por categoria, com sintaxe, exemplo prático e o que cada um faz. Não decore nada — guarde esta página nos favoritos e volte aqui toda vez que travar. A regra de bolso da Ana: quando um comando parecer estranho, ela digita docker COMANDO --help e o próprio Docker lista as flags daquele comando. Todas as saídas de terminal abaixo seguem o formato real do Docker Engine 27.x.

Você vai aprender
  • Os comandos de container, imagem, rede, volume, sistema e Compose — com exemplo de cada.
  • O fluxo típico de um dia de trabalho (a sequência que você mais vai usar).
  • Como é a saída real dos principais no terminal.
  • O atalho de ouro: docker COMANDO --help abre a ajuda daquele comando.
  • Referências cruzadas: instruções do Dockerfile, campos do compose, flags do docker run.

O fluxo de um dia de trabalho

Antes das tabelas, a sequência que a Ana usa o dia inteiro no notebook — memorize essa ordem, ela resolve 90% das situações:

$ docker pull nginx:alpine                 « 1. baixa a imagem (uma vez só)
$ docker run -d --name web -p 8080:80 nginx:alpine   « 2. cria e inicia o container
$ docker ps                                 « 3. confirma que está no ar
$ docker logs web                           « 4. vê o que o app imprimiu
$ docker exec -it web sh                    « 5. entra no container para debugar
$ docker stop web                           « 6. para quando acabar
$ docker rm web                             « 7. apaga o container parado
$ docker rmi nginx:alpine                   « 8. (opcional) apaga a imagem se não for usar mais

Se algo der errado no meio, o trio de diagnóstico é sempre: docker ps -a → docker logs NOME → docker inspect NOME. A página Erros comuns lista o que cada um revela.

Containers

SintaxeExemploO que faz
docker run [OPÇÕES] IMAGEM [COMANDO]docker run -d --name web -p 8080:80 nginx:alpineCria e inicia um container a partir de uma imagem. Devolve o ID completo (64 hex); no ps aparecem os 12 primeiros. As opções principais estão na cola de flags do docker run.
docker ps [-a] [-q]docker ps -aLista containers: só os rodando, ou todos com -a (inclui parados); -q devolve só os IDs (útil em scripts: docker rm $(docker ps -aq)).
docker start NOMEdocker start webInicia um container que está parado. Devolve o nome do container.
docker stop [-t N] NOMEdocker stop webPara um container rodando: manda SIGTERM, espera -t segundos (padrão 10) e manda SIGKILL se não parar.
docker restart NOMEdocker restart webPara e inicia o mesmo container de novo (é um stop + start).
docker rm [-f] NOMEdocker rm webApaga um container parado. Com -f, apaga mesmo rodando (manda SIGKILL).
docker logs [-f] [--tail N] NOMEdocker logs -f webMostra a saída (stdout/stderr) que o container produziu. -f acompanha ao vivo; --tail 100 mostra só as últimas 100 linhas.
docker exec [-it] NOME COMANDOdocker exec -it web shRoda um comando dentro de um container que já está rodando (diferente do run, que cria um novo).
docker inspect NOMEdocker inspect webDevolve todos os detalhes em JSON: rede, volumes, imagem, estado, variáveis. Com --format dá para extrair um campo só (ver exemplos abaixo).
docker stats [NOME]docker statsUso de CPU, memória, rede e disco dos containers rodando, atualizando ao vivo (Ctrl+C sai).
docker cp NOME:/caminho ./localdocker cp web:/var/log/nginx/access.log .Copia arquivos de dentro do container para o host (e o inverso: docker cp ./local web:/caminho).
docker rename ANTIGO NOVOdocker rename web siteTroca o nome de um container (útil quando o nome antigo está "preso" num container parado que você quer remover).
$ docker run -d --name web nginx:alpine
a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6
$ docker ps
CONTAINER ID   IMAGE          COMMAND                  CREATED          STATUS          PORTS     NAMES
a1b2c3d4e5f6   nginx:alpine   "/docker-entrypoint.…"   10 seconds ago   Up 10 seconds   80/tcp    web
$ docker stop web
web
$ docker ps -a
CONTAINER ID   IMAGE          STATUS                       PORTS     NAMES
a1b2c3d4e5f6   nginx:alpine   Exited (0) 5 seconds ago               web

Exemplos de inspect com --format (o canivete suisse do diagnóstico):

$ docker inspect web --format '{{.State.Status}}'
exited
$ docker inspect web --format '{{range .NetworkSettings.Ports}}{{.HostPort}}{{end}}'
8080
$ docker inspect web --format '{{json .Mounts}}' | python3 -m json.tool
[]

Imagens

SintaxeExemploO que faz
docker imagesdocker imagesLista as imagens locais (repositório, tag, ID, data, tamanho).
docker pull IMAGEM[:tag]docker pull nginx:alpineBaixa uma imagem de um registry (o padrão é o Docker Hub). Sem tag, baixa :latest.
docker rmi [-f] IMAGEMdocker rmi nginx:alpineApaga uma imagem local (só se nenhum container, mesmo parado, estiver usando ela).
docker build [-t NOME:tag] CAMINHOdocker build -t meuapp:1.0 .Cria uma imagem nova executando as instruções do Dockerfile encontrado no CAMINHO (o . é a pasta atual). A cola de instruções está em ref-dockerfile.
docker tag ORIGEM DESTINOdocker tag meuapp:1.0 ana/meuapp:1.0Cria uma nova tag (apelido) apontando para a mesma imagem — é assim que se prepara o push para o seu usuário no Hub.
docker push IMAGEMdocker push ana/meuapp:1.0Envia a imagem para o registry (precisa de docker login antes).
docker login [-u USUARIO]docker login -u anaAutentica num registry (pede a senha/token no terminal; no CI use token).
docker history IMAGEMdocker history meuapp:1.0Mostra as camadas da imagem, o comando que criou cada uma e o tamanho — ótimo para ver por que a imagem está grande (aula Analisando camadas).
docker save -o arquivo.tar IMAGEMdocker save -o backup.tar meuapp:1.0Exporta a imagem para um arquivo .tar (backup/offline).
docker load -i arquivo.tardocker load -i backup.tarImporta uma imagem de um .tar salvo com save.

Redes

SintaxeExemploO que faz
docker network lsdocker network lsLista as redes (as padrão bridge, host e none já vêm prontas — aula Redes no Docker).
docker network create NOMEdocker network create minha-redeCria uma rede nova do tipo bridge. Devolve o ID da rede.
docker network rm NOMEdocker network rm minha-redeApaga uma rede criada por você (as padrão não podem ser apagadas).
docker network connect REDE CONTAINERdocker network connect minha-rede webLiga um container já existente a uma rede (um container pode estar em várias redes).
docker network inspect NOMEdocker network inspect minha-redeMostra os containers ligados à rede e os IPs internos em JSON.
$ docker network ls
NETWORK ID     NAME      DRIVER    SCOPE
aabbccddeeff   bridge    bridge    local
bbccddeeff11   host      host      local
ccddeeff1122   none      null      local
$ docker network create minha-rede
f6a1b2c3d4e5a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6
$ docker run -d --name web --network minha-rede nginx:alpine   « nasce já na rede nova
$ docker run -d --name api --network minha-rede node:22-alpine
$ docker exec web ping -c 1 api   « dentro da rede, os containers se acham PELO NOME
PING api (172.18.0.3): 56 data bytes
64 bytes from 172.18.0.3: seq=0 ttl=64 time=0.123 ms

Esse ping api funcionando é a prova de que o DNS interno do Docker traduz o nome do container para o IP dele na rede — a base da comunicação entre containers (aula Containers se comunicando por nome).

Volumes

SintaxeExemploO que faz
docker volume lsdocker volume lsLista os volumes nomeados criados na máquina.
docker volume create NOMEdocker volume create dadosCria um volume nomeado (pasta gerenciada pelo Docker em /var/lib/docker/volumes). Devolve o nome.
docker volume rm NOMEdocker volume rm dadosApaga um volume (só se nenhum container estiver usando).
docker volume inspect NOMEdocker volume inspect dadosMostra detalhes em JSON, inclusive o Mountpoint (caminho real no host).
docker volume prunedocker volume pruneApaga todos os volumes que não estão em uso por nenhum container.
$ docker volume create dados
dados
$ docker volume ls
DRIVER    VOLUME NAME
local     dados
$ docker run -d --name db -v dados:/var/lib/postgresql/data postgres:16-alpine
b2c3d4e5f6a1…
$ docker volume inspect dados --format '{{.Mountpoint}}'
/var/lib/docker/volumes/dados/_data

Três formas de montar dados num container (aula Volumes a fundo): volume nomeado (-v dados:/…), bind mount (-v /home/ana/site:/…) e tmpfs (--tmpfs /tmp).

Sistema

SintaxeExemploO que faz
docker system df [-v]docker system dfQuanto espaço em disco imagens, containers, volumes e cache de build ocupam. -v detalha item por item.
docker system prune [-a] [--volumes]docker system prune -aApaga tudo que não está em uso: containers parados, imagens soltas, redes não usadas, cache de build. -a inclui imagens sem tag; --volumes inclui volumes não usados. Devolve o espaço liberado.
docker infodocker infoInformações gerais: quantos containers/imagens existem, driver de armazenamento, SO do host, warnings de configuração.

Compose (vários containers de uma vez)

SintaxeExemploO que faz
docker compose versiondocker compose versionMostra a versão do plugin Compose (v2.x).
docker compose up [-d] [--build]docker compose up -d --buildCria e inicia todos os serviços do docker-compose.yml da pasta atual (rede e volumes também). --build reconstrói as imagens com build:.
docker compose down [-v]docker compose downPara e remove os containers e a rede do projeto. Com -v, remove também os volumes nomeados (cuidado com dados!).
docker compose psdocker compose psLista os containers do projeto Compose.
docker compose logs [-f] [serviço]docker compose logs -f apiLogs de todos os serviços, ou de um só; -f acompanha ao vivo.
docker compose builddocker compose buildReconstrói só as imagens dos serviços que têm build no YAML.
docker compose exec SERVIÇO COMANDOdocker compose exec db psql -U postgresRoda um comando dentro de um serviço rodando (atalho para docker exec no container do serviço).
docker compose -f ARQUIVO updocker compose -f prod.yml up -dUsa outro arquivo em vez do docker-compose.yml padrão (dá para passar vários -f, que são mesclados).
$ docker compose up -d
[+] Running 2/2
 ✔ Container meuapp-db-1   Started
 ✔ Container meuapp-web-1  Started
$ docker compose ps
CONTAINER ID   IMAGE              STATUS          PORTS                  NAMES
c3d4e5f6a1b2   postgres:16-alpine Up 30 seconds   5432/tcp               meuapp-db-1
d4e5f6a1b2c3   meuapp-web:1.0     Up 30 seconds   0.0.0.0:8080->80/tcp   meuapp-web-1

A cola completa dos campos do arquivo YAML está em ref-compose.

Atalho universal: --help

Nenhum comando ficou claro? O próprio Docker explica — e essa é a melhor fonte, porque a ajuda é da versão exata que você está rodando:

$ docker --help
Usage:  docker [OPTIONS] COMMAND
Commands:
  run       Create and run a new container from an image
  ps        List containers
  images    List images
  pull      Download an image from a registry
  …
Run 'docker COMMAND --help' for more information on a command.
$ docker run --help
Usage:  docker run [OPTIONS] IMAGE [COMMAND] [ARG...]
Options:
  -d, --detach          Run container in background and print container ID
  -p, --publish list    Publish a container's port(s) to the host
  -v, --volume list     Bind mount a volume
  --rm                  Automatically remove the container when it exits
  …

Resumo

  • O dia a dia gira em torno de poucos comandos: run, ps, logs, exec, stop, rm, build, compose up/down.
  • Diagnóstico em 3 passos: ps -a → logs → inspect.
  • Imagens: pull/images/build/tag/push; containers: run/ps/stop/rm.
  • Redes e volumes têm comandos próprios (docker network …, docker volume …) e o Compose orquestra tudo com docker compose ….
  • Não lembra uma flag? docker COMANDO --help responde na hora.
