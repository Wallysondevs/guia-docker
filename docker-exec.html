docker exec

docker run cria um container novo. O docker exec roda um comando num container que já está rodando. É a diferença entre "abrir um programa novo" e "digitar um comando na janela que já está aberta".

Você vai aprender
  • docker exec NOME comando: rodar um comando ponctual num container no ar.
  • docker exec -it NOME sh: abrir um shell interativo dentro dele.
  • A diferença entre run (novo) e exec (existente).
  • Erros reais: container parado (is not running) e inexistente (No such container).
  • -e (variável só nesse comando) e -u (trocar de usuário).

A cena: a Ana quer fuçar o Nginx que está no ar

$ docker run -d --name web nginx:alpine
$ docker ps
… Up 10 seconds   web

Em vez de criar outro container, ela entra no web com exec.

Um comando rápido

Missão: rode docker exec web echo olá num container nginx rodando.

$ docker exec web echo "olá do lado de dentro"
olá do lado de dentro
$ docker exec web ls /etc/nginx
conf.d  fastcgi_params  mime.types  modules  nginx.conf  scgi_params  uwsgi_params
$ docker exec web cat /etc/nginx/nginx.conf
user  nginx;
worker_processes  auto;
…         « o arquivo de configuração, lido de dentro do container
docker exec web echo olá
"Rode echo olá dentro do container web e me mostre a saída".
web
O container (nome ou ID curto) — precisa estar rodando.
echo olá
O comando + argumentos, exatamente como você digitaria lá dentro.

Útil para: ver um arquivo de configuração, checar uma variável, rodar um teste, disparar um comando administrativo (ex.: docker exec banco psql -U ana -c "SELECT 1").

Shell interativo: -it no exec

Com -it, em vez de um comando único, você abre um shell dentro do container que já existe — e sair dele não para o container:

$ docker exec -it web sh
/ # ls /
bin  boot  dev  docker-entrypoint.d  docker-entrypoint.sh  etc  home  …
/ # ps aux          « os processos rodando DENTRO do container
PID   USER   COMMAND
  1   root   nginx: master process nginx -g daemon off;
 31   nginx  nginx: worker process
/ # cat /etc/os-release
NAME="Alpine Linux" …
/ # exit            « sai do shell; o container CONTINUA rodando
$ docker ps
… Up 5 minutes   web    « continua no ar ✅

Missão: abra um shell dentro do container web: docker exec -it web sh (no simulador aparece a mensagem de shell interativo; no Docker real você estaría dentro).

Erros reais

Missão: pare o container (docker stop web) e depois tente docker exec web date — veja o erro de container parado.

$ docker stop web
web
$ docker exec web date
Error response from daemon: Container web is not running
Container parado não aceita exec

O exec precisa de um container rodando (ele cria um processo novo dentro dele). Se o container está parado, ou dá docker start nele, ou (se era um teste) rode de novo com docker run. Mensagem real: Container X is not running.

Container inexistente 
$ docker exec nao-existe ls
Error response from daemon: No such container: nao-existe

Nome errado ou já apagado — confira com docker ps -a.

Comando que não existe dentro do container 
$ docker exec web comando-que-nao-existe
OCI runtime exec failed: exec: "comando-que-nao-existe": executable file not found in $PATH: unknown

A imagem Alpine é mínima: nem sempre tem o comando que você espera (ex.: curl não vem no alpine padrão). Instale na hora (apk add curl) ou use uma imagem maior.

Exec no dia a dia: para que a Ana usa

  • Testar a configuração antes de reiniciar: docker exec web nginx -t — o Nginx testa o nginx.conf e diz se tem erro; se tiver, você corrige antes do docker restart web quebrar o site.
  • Entrar no banco para uma query rápida: docker exec -it banco psql -U ana -d minha_loja -c "SELECT count(*) FROM produtos;".
  • Backup de banco: docker exec banco pg_dump -U ana minha_loja > backup.sql (o > redireciona para um arquivo da sua máquina, não do container).
  • Ver se o container enxerga outro serviço (rede interna): docker exec web ping banco ou docker exec web wget -qO- http://banco:5432.
  • Checar processos e memória dentro dele: docker exec web ps aux, docker exec web free -m.
  • Rodar uma tarefa ponctual (migração, seed, limpeza): docker exec api node scripts/limpa-cache.js.

Exec dentro de projetos Compose

Quando o projeto sobe com docker compose up (nível 2), os containers ganham nomes previsíveis (meuprojeto-web-1, meuprojeto-db-1) e o exec funciona igual:

$ docker compose ps
NAME              STATUS    PORTS
meuprojeto-web-1  Up        0.0.0.0:8080->80/tcp
meuprojeto-db-1   Up        5432/tcp
$ docker exec meuprojeto-db-1 psql -U ana -c "SELECT 1"
?column?
 1
Não "conserte na mão" dentro de container de produção

O exec é ótimo para investigar, mas qualquer mudança feita dentro de um container (arquivo editado, pacote instalado) some quando o container for recriado — e em produção containers são recriados o tempo todo. A regra: investigue com exec, mas aplique a correção na imagem (Dockerfile) e redeploy. A exceção: dados em volumes persistem de verdade.

Exec em cadeia e em scripts

Como o exec devolve a saída na tela, dá para usar em scripts e encadear comandos:

$ docker exec web hostname
f3a1b2c3d4e5
$ docker exec api node -e "console.log(process.version)"
v22.11.0                       « a versão do Node DENTRO do container
$ docker exec banco pg_dump -U postgres loja > backup-$(date +%F).sql   « backup com data no nome
$ for c in $(docker ps -q); do docker exec $c sh -c "echo $c: $(date)"; done   « roda em todos os rodando

Copiar arquivo com docker cp

$ docker cp ./config.json web:/etc/nginx/conf.d/   « manda arquivo para dentro do container rodando
$ docker cp web:/var/log/nginx/access.log ./logs/   « traz arquivo de dentro para sua máquina

Funciona com container rodando ou parado — diferente do exec.

exec não muda a imagem

Se você entrar num container e instalar um pacote (apk add curl), rodar um apt, ou editar um arquivo, essa mudança vale só naquele container. Se ele for apagado e recriado, a mudança some. Para mudança permanente: altere o Dockerfile e rebuild (nível 2).

Exit code do exec (útil em scripts)

O docker exec devolve o código de saída do comando que rodou dentro do container — dá para usar em condicionais:

$ docker exec web test -f /etc/nginx/nginx.conf && echo "config existe"
config existe
$ docker exec web nginx -t; echo "codigo: $?"
nginx: the configuration file … syntax is ok
codigo: 0
$ docker exec api node -e "process.exit(3)"; echo "codigo: $?"
codigo: 3                       « o código 3 veio de dentro do container

Variáveis só para aquele exec

$ docker exec -e MODO=teste api node -e "console.log(process.env.MODO)"
teste

exec com shell encadeado (vários comandos)

Para rodar vários comandos de uma vez dentro do container, passe um sh -c com o conjunto:

$ docker exec web sh -c "ls /etc/nginx && nginx -v && ps aux | head -3"
conf.d  fastcgi_params  mime.types  modules  nginx.conf  scgi_params  uwsgi_params
nginx version: nginx/1.27.3
PID   USER   COMMAND
  1   root   nginx: master process nginx -g daemon off;

O sh -c "…" abre um shell dentro do container, roda tudo e sai — sem precisar de -it.

Quando usar exec vs recriar o container

SituaçãoMelhor caminho
Ver um arquivo, rodar um teste, uma query rápidadocker exec ✅
Mudar configuração que já está na imagem (ex.: instalar pacote, trocar arquivo de config padrão)Recriar com a imagem nova (Dockerfile) — mudança no exec não persiste
Container caiu e você quer saber por quêdocker logs primeiro; se precisar fuçar com ele parado, docker run --rm -it … sh em vez de start
Precisa entrar várias vezes no mesmo containerdocker exec -it X sh quantas vezes quiser — o container segue Up

Resumo

  • docker exec NOME comando roda um comando dentro de um container que já está rodando e mostra a saída.
  • docker exec -it NOME sh abre um shell interativo lá dentro; ao sair (exit), o container continua no ar.
  • run = container novo; exec = comando num existente. attach = grudar na saída do processo principal de um que já roda.
  • Variações: -d (segundo plano), -e VAR=…, -u usuário, -w diretório.
  • Erros reais: Container X is not running (parado), No such container: X (não existe), executable file not found in $PATH (comando não está na imagem).
