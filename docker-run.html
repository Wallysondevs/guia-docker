docker run — anatomia do comando

O docker run é o comando que você mais vai usar: ele cria e inicia um container a partir de uma imagem. Parece simples, mas tem dezenas de opções. Nesta aula, cada uma é explicada com um exemplo real — e a Ana vai usá-las para subir o primeiro site dela no notebook.

Você vai aprender
  • A sintaxe geral: docker run [OPÇÕES] IMAGEM [COMANDO].
  • Cada opção essencial: -d, --name, -p, -e, -v, -it, --rm, --restart.
  • Sobrescrever o comando padrão da imagem (depois do nome dela).
  • A tabela "quando usar cada opção".
  • Os erros reais: imagem inexistente, nome repetido, falta de argumento.
Sintaxe geral 
docker run [OPÇÕES] IMAGEM [COMANDO] [ARGS…]

As OPÇÕES (flags) moldam o container: -d, -p, -e, -v, --name… A IMAGEM é a receita. O COMANDO opcional sobrescreve o comando padrão da imagem.

O básico

$ docker run hello-world

Cria um container da imagem hello-world, inicia, mostra a saída no seu terminal e, quando o container termina, devolve o terminal. O container fica parado (não some — veja docker ps -a na aula primeiro container).

Anatomia completa de um comando real

Este é o comando que a Ana vai usar para publicar o site dela — cada pedaço explained:

$ docker run -d -p 8080:80 --name meu-site nginx:alpine
docker
O cliente (CLI).
run
"Crie e inicie um container novo".
-d
detach: roda em segundo plano e devolve o terminal na hora (imprime só o ID do container).
-p 8080:80
publish: porta 8080 da máquina da Ana → porta 80 do container. Formato -p HOST:CONTAINER (aula Portas).
--name meu-site
Dá o nome meu-site ao container (em vez do aleatório tipo keen_blackwell). Nomes facilitam stop, logs, exec.
nginx:alpine
A imagem (receita) — última parte antes de um comando opcional.

-d: rodar em segundo plano (detach)

Sem -d, o terminal fica preso no container (bom para programas que imprimem na tela, como o hello-world). Com -d, o container roda "soltinho" e o comando devolve na hora o ID do container:

$ docker run -d nginx:alpine
f3a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5
$ docker ps
CONTAINER ID   IMAGE          STATUS         PORTS     NAMES
f3a1b2c3d4e5   nginx:alpine   Up 5 seconds   80/tcp    keen_blackwell

Repare: o Nginx fica rodando e expõe a porta 80/tcp dentro da rede do container — só que ainda não dá para acessar de fora (isso é o -p, na aula portas).

Missão: rode docker run -d nginx:alpine para subir um Nginx em segundo plano e depois veja com docker ps.

--name: dar um nome ao container

Sem --name, o Docker inventa um nome aleatório (keen_blackwell, clever_curie-42…). Com a opção, você escolhe:

$ docker run -d --name meu-site nginx:alpine
$ docker ps
… NAMES
… meu-site

O nome precisa ser único na máquina (dois containers não podem ter o mesmo nome). É útil para scripts e para os comandos que usam o nome: docker stop meu-site, docker logs meu-site, docker exec meu-site ….

Erro real: nome já existe 
$ docker run -d --name meu-site nginx:alpine
$ docker run -d --name meu-site redis:7-alpine
docker: Error response from daemon: Conflict. The container name "/meu-site" is already in use by container "f3a1…". You have to remove (or rename) that container to be able to reuse that name.

Como consertar: escolha outro nome (--name meu-site2) ou remova o antigo (docker rm -f meu-site).

-p: publicar portas

O container tem a sua própria rede interna. Para acessar de fora, você publica uma porta do container numa porta da sua máquina:

-p 8080:80
Porta 8080 da sua máquina → porta 80 do container. Formato: -p HOST:CONTAINER.
-p 127.0.0.1:8080:80
Publica só no localhost (mais seguro — ninguém de fora acessa).
-p 80
Porta aleatória da máquina → porta 80 do container (o Docker escolhe a porta do host; veja qual foi no docker ps).
$ docker run -d -p 8080:80 --name meu-site nginx:alpine
$ docker ps
… PORTS
… 0.0.0.0:8080->80/tcp

Agora http://localhost:8080 abre o Nginx do container. A aula Publicando portas detalha todas as variações.

-e: variáveis de ambiente

$ docker run -d -e POSTGRES_PASSWORD=segredo -e POSTGRES_USER=ana --name banco postgres:16-alpine

Define variáveis dentro do container na hora da criação. Muitas imagens oficiais (postgres, mysql, redis…) são configuradas assim — a página da imagem no Hub lista as variáveis que ela aceita. A aula Variáveis de ambiente mostra mais, inclusive --env-file.

-v: volumes (pastas que persistem)

$ docker run -d -v /home/ana/site:/usr/share/nginx/html:ro --name meu-site nginx:alpine

Monta uma pasta da sua máquina dentro do container. Formato: -v HOST:CONTAINER:ro (ro = somente leitura). Sem volume, tudo que o container grava some quando ele é apagado. A aula Volumes aprofunda.

-it: modo interativo

$ docker run -it --rm python:3.12-slim python
>>> print("olá do container")
olá do container
>>> 2 + 2
4
>>> exit()

-i mantém a entrada aberta (o container recebe o que você digita); -t aloca um terminal (prompt, cores, Ctrl+C funciona). Juntos, você entra "dentro" do container. Para sair sem parar o container: Ctrl+P Ctrl+Q (aula modo interativo).

--rm: apagar ao sair

$ docker run --rm hello-world   « rodou, imprimiu e o container foi apagado sozinho
$ docker ps -a                    « não aparece nada

Ótimo para testes e comandos descartáveis — não deixa container parado enchendo a lista.

Sobrescrevendo o comando da imagem

Toda imagem tem um comando padrão (o que roda quando você não diz nada — no nginx é o próprio servidor; no python é o interpretador). Você pode trocar esse comando pondo ele depois do nome da imagem:

$ docker run --rm python:3.12-slim python -c "print('oi do python')"
oi do python
$ docker run --rm alpine echo "oi do alpine"
oi do alpine
$ docker run --rm alpine ls /          « lista a raiz do container
bin  dev  etc  home  lib  …

Isso é muito comum: a imagem postgres, por exemplo, inicia o banco por padrão; mas docker run postgres psql abre o cliente de linha de comando dentro dela. A ordem é sempre: docker run [OPÇÕES] IMAGEM [COMANDO…] — primeiro a imagem, depois o comando.

Juntando tudo: exemplo real

A API da Ana, com tudo de uma vez:

$ docker run -d \
    --name minha-api \
    -p 3000:3000 \
    -e NODE_ENV=production \
    -v /home/ana/dados:/app/dados \
    --restart unless-stopped \
    node:22-alpine node server.js
--restart unless-stopped
Se o container cair (ou a máquina reiniciar), o Docker liga ele de novo sozinho — essencial para serviços. Opções: no, always, on-failure, unless-stopped.
node server.js
O comando que roda dentro do container (em vez do padrão da imagem).

Tabela: quando usar cada opção

OpçãoQuando usar
-dServiços que ficam rodando (web, banco, API) — você não quer o terminal preso.
-itQuando você quer entrar no container (shell, REPL, debug).
--nameSempre que o container for importante (facilita stop/logs/exec e scripts).
-pQuando o serviço precisa ser acessado de fora (site, API).
-eQuando a imagem precisa de configuração (senhas, portas internas, modo).
-vQuando os dados precisam sobreviver ao container (banco de dados, uploads).
--rmTestes rápidos e containers descartáveis (hello-world, scripts one-shot).
--restart unless-stoppedServiços de produção que devem voltar sozinhos se cair.
COMANDO depois da imagemQuando você quer rodar outra coisa dentro da imagem (ex.: sh, psql).

Erros reais do docker run

Esqueci a imagem

Missão: rode docker run sem nada depois e veja o erro.

$ docker run
docker: 'docker run' requires at least 1 argument.
See 'docker run --help'.
Imagem que não existe

Missão: rode docker run imagem-que-nao-existe e veja o que acontece quando a imagem não existe no Hub.

$ docker run imagem-que-nao-existe
Unable to find image 'imagem-que-nao-existe' locally
imagem-que-nao-existe: Pulling from library/imagem-que-nao-existe
Status: Downloaded newer image for imagem-que-nao-existe
docker: pull access denied for imagem-que-nao-existe, repository does not exist or may require 'docker login'.
See 'docker run --help'.

O Docker tentou baixar (pull automático), o Hub disse que o repositório não existe, e o comando falhou. Nome de imagem errado = esse erro. Confira o nome no Hub.

Já vimos acima: Conflict. The container name "/meu-site" is already in use… — cada nome é único por máquina.

Resumo

  • Sintaxe: docker run [OPÇÕES] IMAGEM [COMANDO…] — opções moldam o container; depois da imagem vem um comando opcional que sobrescreve o padrão.
  • -d roda em segundo plano (devolve o ID); sem ele, o terminal fica grudado na saída do container.
  • --name dá nome único e legível; -p H:C publica porta do host no container; -e passa variável; -v monta pasta; -it entra no container; --rm apaga ao sair; --restart religa sozinho.
  • Erros reais: falta a imagem (requires at least 1 argument), imagem inexistente (pull access denied), nome repetido (Conflict. The container name … is already in use).
  • Depois do run, confira com docker ps — a próxima aula.
