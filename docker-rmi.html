docker rmi — removendo imagens

Imagens ocupam espaço em disco (a máquina da Ana já tem ~860MB só nas 6 imagens iniciais). O docker rmi apaga uma imagem da máquina local —注意: não apaga nada do Docker Hub; o que está publicado lá continua lá para todo mundo baixar.

Você vai aprender
  • Remover por nome:tag e por ID.
  • Remover várias de uma vez e o -f (forçar).
  • O erro real quando a imagem está em uso por um container.
  • O que acontece com a tag quando a imagem ainda tem outro apelido.
  • Limpar imagens dangling (<none>) com prune.

A cena: a Ana quer liberar espaço

Depois de testar o hello-world várias vezes, a Ana decide apagar a imagem dele do notebook (ela pode baixar de novo quando quiser — está no Hub):

Por nome ou ID

Missão: remova a imagem hello-world com docker rmi hello-world (se um container dela existir, pare e remova antes).

$ docker rmi hello-world
Untagged: hello-world:latest
Deleted: sha256:a1b2c3d4e5f6…
$ docker images
REPOSITORY   TAG          IMAGE ID       CREATED         SIZE
nginx        alpine       b2c3d4e5f6a1   5 days ago      48.2MB
…                              « hello-world sumiu
Untagged: hello-world:latest
O "apelido" (tag) foi removido — a linha hello-world:latest some da lista.
Deleted: sha256:a1b2…
As camadas da imagem foram apagadas do disco (só as que não são compartilhadas com outra imagem — se outra imagem usa a mesma camada base, ela continua).

Também dá para usar o ID no lugar do nome: docker rmi a1b2c3d4e5f6 (os primeiros caracteres bastam).

Missão: tente apagar uma imagem que não existe: docker rmi imagem-que-nao-existe. Veja o erro real.

$ docker rmi imagem-que-nao-existe
Error: No such image: imagem-que-nao-existe

Várias de uma vez

$ docker rmi imagem1 imagem2 imagem3     « vários argumentos
$ docker rmi $(docker images -q)          « apaga TODAS as imagens locais (cuidado!)
$ docker rmi nginx:alpine redis:7-alpine   « só essas duas tags
Cuidado com docker rmi $(docker images -q)

Isso apaga todas as imagens da máquina de uma vez (menos as que estão em uso por algum container, que dão erro). Em máquina de desenvolvimento.testes, tudo bem; em máquina de produção, cheque duas vezes antes.

Erro real: imagem em uso por container

Se existir qualquer container (rodando ou parado) criado dessa imagem, o Docker recusa:

$ docker run --name teste hello-world    « criou um container (parado, Exited)
$ docker rmi hello-world
Error response from daemon: conflict: unable to remove repository reference "hello-world:latest" (must force) - container teste is using its referenced image

Como consertar, em ordem de preferência:

  1. Remova o container primeiro: docker rm teste e depois docker rmi hello-world — é o caminho limpo.
  2. Ou force: docker rmi -f hello-world — apaga a imagem e os containers parados que a usavam continuam com uma cópia da camada gravável, mas não dá para recriar novos dessa imagem.

Quando a imagem tem duas tags (apelidos)

Se a mesma imagem tem dois nomes (ex.: nginx:alpine e meu-nginx:dev, mesmo ID), o rmi só tira uma tag por vez — a imagem só sai do disco quando a última tag dela for removida:

$ docker tag nginx:alpine meu-nginx:dev
$ docker rmi nginx:alpine
Untagged: nginx:alpine
$ docker images
REPOSITORY   TAG       IMAGE ID       SIZE
meu-nginx    dev       b2c3d4e5f6a1   48.2MB    « a imagem continua, com o outro nome
$ docker rmi meu-nginx:dev
Untagged: meu-nginx:dev
Deleted: sha256:b2c3…                       « agora sim apagou as camadas

Imagens dangling (<none>) e prune

Builds antigos sem tag viram <none>:<none> (aula docker images). Para limpar só elas:

$ docker image prune
WARNING! This will remove all dangling images.
Are you sure you want to continue? [y/N] y
Deleted Images:
deleted: sha256:a1b2…
Total reclaimed space: 148MB

E para limpar tudo que não está em uso (containers parados + imagens dangling + redes + cache de build): docker system prune — aula docker system prune.

Quanto espaço o rmi devolve?

Antes e depois dá para conferir com docker system df (aula docker system df):

$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          6         3         861MB     400MB (46%)
$ docker rmi hello-world postgres:16-alpine
Untagged: hello-world:latest
Deleted: sha256:a1b2c3d4e5f6…
Untagged: postgres:16-alpine
Deleted: sha256:d4e5f6a1b2c3…
$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          4         2         616MB     155MB (25%)

O SIZE de cada imagem é a soma das camadas próprias dela. Quando você apaga uma imagem, só somem as camadas que nenhuma outra imagem usa — as camadas base compartilhadas (tipo o Alpine) continuam no disco porque outras imagens ainda precisam delas. É por isso que apagar uma imagem às vezes devolve menos espaço do que o SIZE dela.

Ordem certa de limpeza

  1. Veja o que tem: docker ps -a (containers) e docker images (imagens).
  2. Apague os containers que não precisa mais: docker rm nome (ou docker rm -f se estiver rodando).
  3. Depois apague as imagens que não usa: docker rmi nome:tag.
  4. Para uma limpeza geral: docker system prune (remove containers parados, imagens dangling, redes e cache não usados).
  5. Conferiu o espaço de volta: docker system df.
Não apague a imagem achando que "o container vai continuar"

Um container rodando impede o rmi justamente para te proteger. Mas um container parado também impede — e se você usar -f, a imagem sai e aquele container parado vira inútil (não dá para dar start de novo sem a imagem). Se o container parado tem dados na camada gravável, eles somem com docker rm — então só apague quando tiver certeza (dados importantes devem estar em volumes).

Antes de apagar: salve a imagem (docker save/load)

Se a imagem foi criada por você (build local) e ainda não está no Hub, apagar é perder o trabalho. Dá para exportar para um arquivo .tar e importar depois (ou levar para outra máquina):

$ docker save -o meuapp-1.0.tar ana/meuapp:1.0     « exporta a imagem (todas as camadas) para um .tar
$ ls -lh meuapp-1.0.tar
-rw-r--r-- 1 ana ana 152M … meuapp-1.0.tar
$ docker rmi ana/meuapp:1.0                          « pode apagar da máquina local
$ docker load -i meuapp-1.0.tar                     « importa de volta quando precisar
Loaded image: ana/meuapp:1.0

Útil para: backup antes de limpar, levar imagem para um servidor sem internet (air-gapped), ou passar para um colega sem publicar no Hub.

Checklist antes de dar rmi

  1. docker ps -a — tem container dessa imagem? (rodando ou parado) → se sim, docker rm primeiro ou -f.
  2. É uma imagem que você criou e não está no Hub? → faça docker save antes.
  3. Quer apagar mesmo ou só liberar espaço? → docker system prune limpa o que não está em uso sem apagar imagens em uso.
  4. Depois, confira: docker images e docker system df.
O que o rmi NÃO faz
  • Não apaga nada do Docker Hub (o que está publicado lá continua público para todo mundo).
  • Não apaga camadas compartilhadas com outras imagens (elas continuam porque outras usam).
  • Não apaga volumes (dados de banco em volume continuam — docker volume rm apaga).

Removendo pelo filtro (com cuidado)

Além de nome e ID, dá para apagar por filtro — útil para limpar imagens velhas de um repositório:

$ docker rmi $(docker images --filter "dangling=true" -q)   « só as <none>
$ docker rmi $(docker images "meuapp" -q)                   « todas as tags do meuapp
$ docker rmi $(docker images --filter "before=meuapp:1.0" -q)  « imagens mais velhas que essa
Não use docker rmi $(docker images -q) "para testar"

Esse comando apaga todas as imagens locais. Se algum container parado usar uma delas, dá erro; se não, a imagem some e você vai precisar dar pull de novo (de novo = download de novo, se não tiver cache). Em máquina de estudo, tudo bem; em máquina de trabalho, cheque duas vezes com docker images antes.

Depois do rmi: confira

$ docker images
…                              « a linha sumiu
$ docker system df
TYPE      TOTAL  ACTIVE  SIZE     RECLAIMABLE
Images    5      2       813MB    352MB (43%)   « o SIZE diminuiu

Rmi de imagem usada por container parado

Lembrete importante: o Docker considera "em uso" qualquer container — rodando ou parado — criado dessa imagem. Então a ordem certa para apagar tudo de um projeto é sempre: primeiro os containers, depois a imagem:

$ docker ps -a
… meu-site  nginx:alpine   Exited (0) …
$ docker rmi nginx:alpine
Error response from daemon: conflict: … container meu-site is using its referenced image
$ docker rm meu-site
meu-site
$ docker rmi nginx:alpine
Untagged: nginx:alpine
Deleted: sha256:b2c3…

Fluxo completo de limpeza da máquina (resumo prático)

$ docker ps -a                    « 1. veja os containers
$ docker stop $(docker ps -q)     « 2. pare os rodando (se quiser manter algum, pare só ele)
$ docker rm $(docker ps -aq)      « 3. apague os containers
$ docker images                   « 4. veja as imagens
$ docker rmi imagem-que-nao-uso  « 5. apague imagem por imagem (ou system prune)
$ docker system df                « 6. confira o espaço recuperado

Resumo

  • docker rmi NOME:TAG (ou ID) apaga a imagem da máquina local — nada muda no Docker Hub.
  • Saída: Untagged: … (saiu da lista) + Deleted: sha256:… (camadas apagadas, se não forem compartilhadas).
  • Erro real: conflict … container X is using its referenced image (must force) → remova o container antes ou use -f.
  • Vários de uma vez: docker rmi img1 img2; cuidado com docker rmi $(docker images -q).
  • Se a imagem tiver duas tags, cada rmi tira uma; as camadas só somem quando sai a última.
  • Dangling <none>: limpe com docker image prune ou docker system prune.
