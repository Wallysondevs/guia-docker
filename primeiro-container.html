Seu Primeiro Container

O hello-world é o "Olá, mundo!" do Docker: uma imagem minúscula (18 kB!) que imprime uma mensagem explicando o que acabou de acontecer e sai. É o comando perfeito para saber que tudo está funcionando — e, nesta aula, para entender cada passo que o Docker deu nos bastidores.

Você vai aprender
  • Rodar docker run hello-world e entender a saída linha por linha.
  • O que o Docker fez nos bastidores: cliente → daemon → pull → create → start → attach.
  • Por que o terminal "travou" um instante e depois voltou.
  • docker ps -a para ver containers que já terminaram, e o que é Exited (0).
  • docker rm para remover o container (sem apagar a imagem).
  • A opção --rm: rodar e já apagar.

A cena: a Ana liga o notebook pela primeira vez

A Ana acabou de instalar o Docker no notebook dela. Para saber se deu certo, ela roda o comando que todo mundo roda primeiro:

Missão: digite docker run hello-world e aperte Enter.

$ docker run hello-world

Hello from Docker!
This message shows that your installation appears to be working correctly.

To generate this message, Docker took the following steps:
 1. The Docker client contacted the Docker daemon.
 2. The Docker daemon pulled the "hello-world" image from the Docker Hub.
 3. The Docker daemon created a new container from that image.
 4. The Docker daemon streamed that output to the Docker client.

O que aconteceu nos bastidores

O docker run hello-world parece um comando só, mas dispara uma conversa entre duas peças — o cliente (o comando docker que você digitou) e o daemon (dockerd, o serviço rodando em segundo plano):

  1. O cliente (docker) mandou o pedido para o daemon (dockerd) pelo socket /var/run/docker.sock.
  2. O daemon viu que a imagem hello-world não estava na máquina e fez o pull automático do Docker Hub (se já tivesse, pulava esse passo).
  3. O daemon criou um container a partir da imagem: uma camada gravável em cima das camadas somente leitura da imagem.
  4. O daemon iniciou o container, que imprimiu a mensagem no terminal e terminou (código de saída 0).
  5. O cliente mostrou a saída na sua tela e devolveu o terminal (por isso parece que "travou um instante": era o download + criação).
cliente (docker)  ──pedido──▶  daemon (dockerd)
                                   │  imagem não existe localmente?
                                   ▼
                              pull do Docker Hub
                                   │
                                   ▼
                              create (camada gravável) ──▶ start ──▶ saída no seu terminal
Palavra do comandoSignificado
dockerO programa cliente (CLI). Sempre começa com ele.
runO subcomando: "crie um container novo a partir dessa imagem e inicie ele agora".
hello-worldA imagem usada (nome = REPOSITORY; sem :tag, vale :latest).

O detalhe importante: run = create + start + attach. Existe o docker create (só cria, parado) e o docker start (liga um já criado) — dá para separar os passos, mas no dia a dia o run faz tudo de uma vez.

Vendo o container que já saiu

Por padrão, docker ps mostra só os containers rodando. O hello-world já terminou (ele só imprime a mensagem e sai), então ele não aparece:

$ docker ps
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES

Lista vazia — mas o container existe, só está parado. Para ver todos, use -a (de all):

Missão: rode docker ps -a para listar todos os containers, inclusive os que já pararam.

$ docker ps -a
CONTAINER ID   IMAGE         COMMAND    CREATED          STATUS                      PORTS   NAMES
7d3a1b9c2e4f   hello-world   "/hello"   20 seconds ago   Exited (0) 18 seconds ago           clever_curie-42

Na coluna STATUS, Exited (0) quer dizer: o container rodou, terminou, e devolveu o código 0 = sucesso. O NAMES é o nome aleatório que o Docker inventou (clever_curie-42 — cientista + número).

Os códigos de saída (exit codes)

StatusSignificado
Up …Está rodando agora.
Exited (0) …Terminou com sucesso (código 0).
Exited (1) …Terminou com erro (código 1 — olhe docker logs).
Exited (137) …Foi morto à força (SIGKILL — típico de docker kill).
CreatedFoi criado mas nunca iniciou (docker create).

Limpando: docker rm

O container parado continua ocupando um espacinho e enchendo a lista do ps -a. Para apagar de vez:

$ docker rm clever_curie-42
clever_curie-42
$ docker ps -a
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES

O comando imprime o nome do container removido (é a confirmação). A lista ficou vazia de novo.

O container sumiu da lista. A imagem hello-world continua na máquina — confirme com docker images. Apagar o "bolo" não apaga a "receita" (aula conceitos). Quem apaga imagem é o docker rmi (aula própria).

Missão: tente remover um container que não existe: docker rm container-que-nao-existe. Veja a mensagem de erro real.

$ docker rm container-que-nao-existe
Error: No such container: container-que-nao-existe

--rm: rodar e já apagar

Para testes rápidos, existe a opção --rm: o container roda, imprime a saída e é apagado automaticamente quando termina — não fica nem na lista do ps -a:

$ docker run --rm hello-world

Hello from Docker!
…
$ docker ps -a
CONTAINER ID   IMAGE   COMMAND   CREATED   STATUS   PORTS   NAMES   « vazio: o --rm já limpou
Dica: para rodar e já apagar o container ao sair, use docker run --rm hello-world. É o padrão para testes rápidos.

Dois jeitos de fazer a mesma coisa

O docker run é um atalho para três operações que existem separadas:

Forma em 1 comandoForma em 3 comandosQuando usar a segunda
docker run hello-worlddocker create --name teste hello-world → docker start -a testeQuando você quer criar o container antes, inspecionar (docker inspect) e só depois ligar
$ docker create --name teste hello-world
7d3a1b9c2e4f…
$ docker ps -a
… STATUS      NAMES
… Created     teste          « criou mas NÃO rodou
$ docker start -a teste      « -a = attach: mostra a saída no terminal

Hello from Docker!
…
$ docker ps -a
… Exited (0) 2 seconds ago   teste

Repare: entre o create e o start, o status era Created — o container existia, parado. O start -a ligou e grudou a saída na tela (o -a é o "attach").

E se a imagem já estiver na máquina?

Na segunda vez que a Ana roda docker run hello-world, a saída muda um pouco: como a imagem já está no disco, o Docker pula o download e cria direto:

$ docker run hello-world
9f8e7d6c5b4a

Hello from Docker!
…

No Docker de verdade, a primeira vez mostra várias linhas de Pulling from library/hello-world (uma por camada baixada); da segunda em diante, aparece só Using default tag: latest / a imagem local é usada na hora. É por isso que o segundo run é instantâneo.

Erros comuns nesta primeira aula

Cannot connect to the Docker daemon

O serviço do Docker não está rodando. No Linux: sudo systemctl start docker. No Docker Desktop: abra o app. Detalhes na aula Instalar o Docker.

permission denied while trying to connect to the Docker daemon socket

Seu usuário não está no grupo docker: sudo usermod -aG docker $USER e depois newgrp docker (ou saia e entre de novo). Também na aula de instalação.

A saída mostra "pull access denied" para outra imagem

Se você trocar hello-world por um nome que não existe no Hub, o Docker responde pull access denied … repository does not exist or may require 'docker login'. A imagem hello-world existe e é pública — é por isso que ela é o teste padrão.

Resumo

  • docker run hello-world é o teste de fumaça: baixa a imagem (se precisar), cria o container, inicia e mostra a saída.
  • Nos bastidores: cliente → daemon → pull → create → start → attach — a mensagem da imagem explica os 4 passos.
  • docker ps = só os rodando; docker ps -a = todos, inclusive parados (Exited (0) = terminou com sucesso).
  • docker rm NOME apaga o container e imprime o nome como confirmação; a imagem não é apagada.
  • docker run --rm … roda e apaga sozinho ao terminar — ótimo para testes.
  • Erros de "primeira vez": daemon parado (Cannot connect…) e permissão no socket (permission denied) — os dois resolvidos na aula de instalação.
