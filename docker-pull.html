docker pull — baixando imagens

Quando você dá docker run numa imagem que não existe na máquina, o Docker baixa sozinha. Mas dá para baixar antes com docker pull — útil para preparar o ambiente com antecedência (num servidor novo, por exemplo, você já deixa as imagens prontas antes de subir a aplicação).

Você vai aprender
  • A sintaxe: docker pull [REGISTRY/]NAMESPACE/REPOSITÓRIO[:TAG].
  • A ler a saída do pull linha por linha (camadas, digest, status).
  • Como as camadas (layers) são reutilizadas entre imagens (Already exists).
  • Pull com tag específica e pull de imagem que já existe (up to date).
  • O erro real quando o repositório não existe (pull access denied).

O comando

A Ana quer testar um Linux bem pequeno no notebook dela — o Alpine, que pesa ~5MB. Ela baixa antes de rodar:

Missão: rode docker pull alpine para baixar a imagem alpine (um Linux minúsculo de ~5MB).

$ docker pull alpine
Using default tag: latest
latest: Pulling from library/alpine
8e402f132d08: Pull complete
Digest: sha256:be1a…
Status: Downloaded newer image for alpine:latest
docker.io/library/alpine:latest

Anatomia da saída

Using default tag: latest
Você não escreveu :tag, então o Docker assumiu :latest.
latest: Pulling from library/alpine
De onde vem: o repositório alpine do namespace library (oficiais), tag latest, no registry padrão (Docker Hub).
8e402f132d08: Pull complete
Cada linha é uma camada (layer) da imagem, identificada por um hash. Essa baixou inteira ("Pull complete").
Digest: sha256:be1a…
O hash de segurança de todo o conteúdo da imagem — serve para conferir integridade e para fixar a versão exata (alpine@sha256:…).
Status: Downloaded newer image for alpine:latest
Resumo: baixou uma imagem nova.
docker.io/library/alpine:latest
O nome completo, com o registry explícito — é esse endereço que fica gravado na sua máquina.

Com tag específica

Quase sempre você não quer o :latest — quer uma versão fixa. Basta escrever a tag:

$ docker pull node:22-alpine
22-alpine: Pulling from library/node
…
Status: Downloaded newer image for node:22-alpine
docker.io/library/node:22-alpine
$ docker pull postgres:16-alpine
$ docker pull python:3.12-slim
$ docker images
REPOSITORY   TAG          IMAGE ID       CREATED         SIZE
node         22-alpine    c3d4e5f6a1b2   1 week ago      189MB
postgres     16-alpine    d4e5f6a1b2c3   3 days ago      245MB
python       3.12-slim    f6a1b2c3d4e5   4 days ago      132MB
…

Sem tag, o Docker baixa a :latest. A aula Tags e versões explica como escolher a tag certa e por que evitar :latest em produção.

Camadas (layers): o truque da economia

Toda imagem é feita de camadas só de leitura, empilhadas (lembra da aula de conceitos?). Quando você baixa uma imagem, só as camadas que você ainda não tem são transferidas:

$ docker pull nginx:alpine
alpine: Pulling from library/nginx
a1b2c3d4e5f6: Already exists          « camada base que JÁ tenho (veio com o alpine puro)
e5f6a1b2c3d4: Pull complete          « camada nova do nginx
Status: Downloaded newer image for nginx:alpine

Already exists = essa camada já estava no seu disco (compartilhada com outra imagem) e não ocupou download nem espaço novo. Isso deixa os pulls seguintes muito rápidos e economiza disco: imagens que compartilham camadas não ocupam espaço duplicado. É por isso que 10 imagens baseadas em Alpine não ocupam 10× o espaço do Alpine.

Linha do pullSignificado
xxxx: Pull completeCamada baixada agora
xxxx: Already existsCamada que você já tinha — reutilizada, sem download
xxxx: Downloading / ExtractingBaixando / descompactando agora (barra de progresso)
Status: Downloaded newer image for XTerminou: imagem nova baixada
Status: Image is up to date for XVocê já tinha essa versão exata — nada foi baixado

Pull de imagem que já existe

Se a imagem (com aquela tag exata) já está na sua máquina, o pull não baixa nada de novo:

Missão: rode docker pull nginx:alpine — como a imagem já está na máquina da Ana, a resposta diz que está "up to date".

$ docker pull nginx:alpine
nginx:alpine: Image is up to date

Útil para scripts de "garanta que a imagem existe": rode o pull e siga em frente, tenha baixado agora ou já estivesse aí.

Quando a imagem não existe

Erro real: repositório inexistente 
$ docker pull imagem-que-nao-existe
Using default tag: latest
latest: Pulling from library/imagem-que-nao-existe
docker: Error response from daemon: pull access denied for imagem-que-nao-existe, repository does not exist or may require 'docker login'.
See 'docker run --help'.

Causas comuns: nome digitado errado, repositório privado (precisa de docker login) ou imagem que deixou de existir. Confira o nome exato na página da imagem no Docker Hub — e os selos de confiança na aula imagens oficiais.

Erro: sem internet ou registry fora do ar 
$ docker pull nginx:alpine
…
docker: error pulling image: Get "https://registry-1.docker.io/v2/": dial tcp: connect: network is unreachable

O pull fala com o registry pela internet. Sem rede (ou com proxy bloqueando), dá esse erro. Não é problema da imagem — é a conexão.

De onde o pull baixa? O registry no nome

O endereço completo de uma imagem é registry/namespace/repo:tag. Se você não escreve o registry, o Docker usa docker.io (o Hub):

Você escreveO pull vai buscar em
alpinedocker.io/library/alpine:latest
ana/meuapp:1.0docker.io/ana/meuapp:1.0
ghcr.io/empresa/app:2.3ghcr.io/empresa/app:2.3 (GitHub Container Registry)
registry.empresa.com/time/app:devo registry privado da empresa (pode exigir docker login)

Depois de baixar, o nome completo fica gravado na sua máquina — é o que aparece na coluna REPOSITORY do docker images (sem o docker.io/ na frente, para ficar curto).

Atualizando uma imagem: pull de novo pega a versão nova da tag

Atenção numa pegadinha clássica: tags são mutáveis. Se o nginx:alpine de hoje é a versão X, amanhã pode ser a X+1 (quem publica decide). Dar docker pull nginx:alpine de novo baixa a versão nova se ela mudou — e aí aparecem duas linhas no docker images: a tag agora aponta para o ID novo, e o antigo vira <none> (dangling):

$ docker images nginx
REPOSITORY   TAG       IMAGE ID       CREATED        SIZE
nginx        alpine    b2c3d4e5f6a1   5 days ago     48.2MB
$ docker pull nginx:alpine          « uma semana depois…
Status: Downloaded newer image for nginx:alpine
$ docker images
REPOSITORY   TAG       IMAGE ID       CREATED        SIZE
nginx        alpine    e5f6a1b2c3d4   2 days ago     49.1MB   « tag agora aponta pro novo
<none>     <none>    b2c3d4e5f6a1   5 days ago     48.2MB   « o antigo virou dangling

Isso é ótimo para atualizar (pull + recriar o container pega a versão nova), mas perigoso se você esperava a mesma coisa de sempre. Em produção, fixe a versão por digest: docker pull nginx@sha256:abc123… — o digest nunca muda.

Baixar pelo digest: a trava imutável

Quer baixar exatamente a mesma imagem que rodou ontem, sem risco da tag ter mudado? Use o digest no lugar da tag, com @:

$ docker pull alpine@sha256:be1a…
alpine@sha256:be1a…: Pulling from library/alpine
Status: Downloaded newer image for alpine@sha256:be1a…

Onde achar o digest: na página da tag no Docker Hub (canto superior direito, botão "Copy digest") ou na saída do seu próprio docker pull (linha Digest: sha256:…). No Dockerfile e no Compose também dá: FROM alpine@sha256:…, image: postgres:16@sha256:….

Imagens grandes: o que esperar

Algumas imagens são grandes (a node:22-bookworm passa de 1GB). O pull mostra o progresso de cada camada (Downloading / Extracting com barra de progresso). Dicas:

  • Prefira variantes alpine/slim — baixam em segundos.
  • Se a rede cai no meio, rode o pull de novo: as camadas já baixadas são aproveitadas (Already exists) e só o resto baixa.
  • Em CI/CD, usa-se cache de imagens para o pull ser instantâneo.

Pull em privado: docker login

Repositórios privados (da sua empresa, ou seus no Hub) pedem autenticação. Faça login uma vez e o pull/run passam a funcionar:

$ docker login                          « loga no Docker Hub (pede usuário e senha/token)
Login Succeeded
$ docker login registry.empresa.com     « ou num registry privado da empresa
$ docker pull registry.empresa.com/time/app:dev
dev: Pulling from time/app
Status: Downloaded newer image for registry.empresa.com/time/app:dev

Para sair: docker logout. Dica: no Hub, use um Access Token (Account Settings → Security) no lugar da senha — dá para revogar sem trocar a senha da conta.

Erro de login comum 
$ docker pull empresa-privada/app:1.0
docker: pull access denied for empresa-privada/app, repository does not exist or may require 'docker login'

Ou o repositório é privado e você não logou, ou o nome está errado. Rode docker login e tente de novo; se continuar, confira o nome exato no Hub/site interno.

Resumo

  • docker pull NOME[:TAG] baixa uma imagem do registry (padrão: Docker Hub) para a sua máquina; sem tag, vale :latest.
  • Saída: Pulling from library/…, uma linha por camada (Pull complete / Already exists), Digest: sha256:… e Status: Downloaded newer image.
  • Camadas compartilhadas não são baixadas de novo nem ocupam espaço duplicado — é a economia do Docker.
  • Pull de novo na mesma imagem → Image is up to date (nada baixa).
  • Erro real: pull access denied … repository does not exist (nome errado ou repositório privado sem login).
  • Depois de baixar, confira com docker images; para rodar, docker run.
