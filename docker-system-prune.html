docker system prune — limpar a máquina

Com o tempo, a máquina junta containers parados, imagens órfãs, redes sem uso e cache de build — a aula anterior (docker system df) mostrou como ver tudo isso na coluna RECLAIMABLE. O docker system prune varre esse entulho de uma vez e devolve o espaço: é o comando de faxina do Docker.

Você vai aprender
  • O que o docker system prune remove por padrão (e o que ele não remove).
  • -a: remover também as imagens não usadas (não só as dangling).
  • --volumes: por que essa flag é perigosa.
  • -f: rodar sem a pergunta de confirmação (scripts/CI) e --filter until=24h.
  • Os prunes mirados: container/image/volume/network prune.
  • Conferir o antes e o depois com docker system df — inclusive com --format.

O básico (com confirmação)

Sem nenhuma flag, o prune remove apenas o que não está em uso:

  • todos os containers parados (rodando não entra);
  • todas as redes que nenhum container está usando;
  • todas as imagens dangling (as <none>: <none>, sem tag — aula docker system df -v);
  • todo o cache de build dangling.

Ele sempre mostra o aviso e pede confirmação (y + Enter) — no Docker real, nada acontece sem o seu "sim":

$ docker system prune
WARNING! This will remove:
  - all stopped containers
  - all networks not used by at least one container
  - all dangling images
  - all dangling build cache

Are you sure you want to continue? [y/N] y
Deleted Containers:
c3d4e5f6a1b2
f6a1b2c3d4e5

Deleted Images:
untagged: hello-world:latest
deleted: sha256:a1b2c3d4e5f6a1b2c3d4e5f6…

Total reclaimed space: 1.24GB

Repare na última linha: Total reclaimed space diz quanto foi recuperado — é a mesma conta que apareceria na coluna RECLAIMABLE do docker system df.

Missão: rode docker system prune no terminal (no simulador ele não pergunta; no Docker real, confirme com y) e veja a linha Total reclaimed space no final.

Missão: agora rode docker system prune -f — com -f a faxina acontece sem pedir confirmação.

Anatomia das flags

docker system prune
limpa os objetos do Docker que não estão em uso.
-a
também remove todas as imagens sem container (não só as dangling).
--volumes
também remove os volumes locais sem uso — perigoso com dados.
-f
não mostra o aviso nem pede confirmação.
--filter until=24h
limita a limpeza ao que foi criado há mais de 24 horas.

-f: sem perguntar (scripts e CI)

Com -f (ou --force), o comando não mostra o WARNING nem pergunta nada:

$ docker system prune -f
Deleted Containers:
a1b2c3d4e5f6

Total reclaimed space: 812MB

É o formato para scripts e pipelines de CI (aula Docker em pipelines de CI): num servidor de build, ninguém vai digitar "y", então o agendamento usa -f. Só use quando tiver certeza do que está fazendo — em máquina de desenvolvimento, prefira rodar sem -f e ler o aviso antes.

-a / --all: imagens não usadas também

Sem -a, só as imagens dangling (sem tag) vão embora. Com -a, o prune remove todas as imagens que nenhum container está usando — inclusive imagens baixadas com docker pull e tags suas:

$ docker system prune -a
WARNING! This will remove:
  - all stopped containers
  - all networks not used by at least one container
  - all images not used by at least one container
  - all build cache

Are you sure you want to continue? [y/N] y
Deleted Images:
untagged: node:22-alpine
untagged: redis:7-alpine
untagged: python:3.12-slim
deleted: sha256:c3d4e5f6a1b2…
…
Total reclaimed space: 2.71GB
Cuidado: com -a, imagens que você baixou ou buildou e que não estão em uso por nenhum container são apagadas. Se precisar delas de novo, dá para fazer docker pull (imagens do Hub) — mas se a imagem era um build local, sem push para um registry (aula docker tag e push), esse build se perde e precisa ser refeito do zero.

--volumes: a flag mais perigosa

Volumes guardam dados (banco de dados, uploads). O prune padrão não mexe em volumes. Com --volumes, ele apaga todos os volumes que nenhum container está usando — e volume apagado não tem lixeira:

$ docker system prune --volumes
WARNING! This will remove:
  - all stopped containers
  - all networks not used by at least one container
  - all volumes not used by at least one container
  - all dangling images
  - all dangling build cache

Are you sure you want to continue? [y/N] y
Deleted Volumes:
dados-antigos
…
Total reclaimed space: 1.9GB
Nunca rode docker system prune --volumes em produção sem backup. Se um volume guarda dados de um banco (Postgres, MySQL…), esses dados somem na hora. Prefira remover volumes um a um, com docker volume rm NOME (aula docker volume), depois de confirmar com docker volume ls e docker system df -v que ninguém mais usa aquele volume.

--filter: limpar só o que é velho

Em vez de varrer tudo, dá para limitar o prune pelo tempo — until= aceita horas, minutos ou uma data:

$ docker system prune --filter until=24h     « só o que foi criado há mais de 24 horas
$ docker system prune --filter until=168h    « há mais de 1 semana
$ docker system prune --filter label=dev     « só objetos com a label "dev" (ex.: label=dev na hora do build)

É a forma segura de faxina periódica: o que você criou hoje (e pode estar usando agora) fica intacto.

Os prunes mirados: um tipo por vez

Se você quer limpar só uma categoria, existe um comando para cada (todos com as mesmas flags -f e --filter):

ComandoO que remove
docker container pruneSó containers parados
docker image pruneSó imagens dangling (-a = todas as não usadas)
docker volume pruneSó volumes locais sem uso — mesmo cuidado do --volumes
docker network pruneSó redes que nenhum container usa
docker builder pruneSó o cache de build (o Build Cache do df)
$ docker builder prune -f    « limpa só o cache de build (o vilão dos discos cheios)
Total reclaimed space: 1.84GB
$ docker container prune -f
Deleted Containers:
c3d4e5f6a1b2
Total reclaimed space: 6.2MB

Antes e depois: conferindo com docker system df

A forma correta de usar o prune é medir antes e depois — e dá para deixar a medida bonita com --format (templates Go, aula docker inspect):

$ docker system df --format "table {{.Type}}\t{{.Size}}\t{{.Reclaimable}}"
TYPE            SIZE      RECLAIMABLE
Images          1.1GB     874MB (79%)
Containers      18MB      12MB (66%)
Local Volumes   245MB     0B (0%)
Build Cache     1.84GB    1.84GB

$ docker system prune -a -f
…
Total reclaimed space: 2.7GB

$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          2         2         236MB     0B (0%)
Containers      2         2         6MB       0B (0%)
Local Volumes   1         1         245MB     0B (0%)
Build Cache     0         0         0B        0B

Note que Local Volumes continua com 245MB e 0B recuperável: o prune sem --volumes preserva os dados. Esse é o comportamento que você quer 99% das vezes.

Faxina automática (cron / CI)

Muita gente agenda uma limpeza leve toda semana, para o cache de build não crescer sem freio. No ana@notebook, basta um crontab:

$ crontab -e
# todo domingo às 23h: limpa só o que não está em uso há mais de 7 dias, sem perguntar
0 23 * * 0  docker system prune -f --filter until=168h >> /var/log/docker-prune.log 2>&1

E num pipeline de CI (aula Docker em pipelines de CI), o passo final do job costuma ser docker system prune -f para não deixar o servidor de build entupido.

Erros reais

Tentar remover recurso em uso: 
$ docker volume rm dados-postgres
Error response from daemon: remove dados-postgres: volume is in use - [a1b2c3d4e5f6]
O volume está anexado a um container (mesmo parado). Pare/remova o container antes (docker rm -f a1b2c3d4e5f6) ou use docker volume prune, que só pega volumes sem uso.
"WARNING" enganoso: o prune lista o que pode remover, mas se outro processo criar um container entre o aviso e o seu "y", o item simplesmente não é removido (o Docker revalida na hora). Não é erro — é proteção.

Resumo

  • docker system prune remove só o que não está em uso: containers parados, redes sem uso, imagens dangling (<none>) e cache dangling. Sempre pede confirmação; a última linha diz Total reclaimed space.
  • -f pula a confirmação (scripts/CI); -a inclui todas as imagens sem container; --volumes inclui volumes sem uso — perigoso, dados não têm lixeira; --filter until=24h limita por idade.
  • Prunes mirados: docker container/image/volume/network/builder prune.
  • Meça antes e depois com docker system df (ou --format "table {{.Type}}\t{{.Reclaimable}}" para saída de script).
  • Volumes em uso não são apagados — o Docker protege o que está anexado a um container, mesmo parado.
