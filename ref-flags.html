Flags comuns do docker run (cola)

O docker run tem dezenas de opções. Esta cola traz as flags que você vai usar todo dia, agrupadas pela função que cumplen, com sintaxe, exemplo e o efeito de cada uma. A regra geral da sintaxe: docker run [OPÇÕES] IMAGEM [COMANDO] [ARG…] — e atenção: tudo que vem depois do nome da imagem vira comando dentro do container, não flag (veja a última seção).

Você vai aprender
  • Flags de modo: -d, -it, --rm, --pull.
  • Flags de configuração: --name, -p, -e, --env-file, -v, --network, -w, --entrypoint, --user, --hostname, --add-host.
  • Flags de recursos e reinício: --memory/-m, --cpus, --restart.
  • Flags de segurança: --read-only, --tmpfs, --cap-drop/--cap-add, --security-opt, --privileged (com aviso forte), --user.
  • Flags de logs e diagnóstico: --log-driver, --log-opt, --health-cmd, -l/--label, --platform.
  • A tabela final: situação do dia a dia → combinação de flags.

Modo: como o container se comporta

FlagSintaxe / valorO que faz
-d--detachRoda em segundo plano: devolve o ID do container na hora e libera o terminal.
-it-i -tTerminal interativo dentro do container: -i mantém a entrada aberta, -t aloca um terminal (cores, prompt, Ctrl+C). Para sair sem parar o container: Ctrl-P, Ctrl-Q.
--rmsem valorApaga o container automaticamente quando ele termina — ideal para testes e tarefas one-shot (rodar testes, um script, um curl interno).
--pull--pull always (ou missing/never)Força o docker pull da imagem antes de rodar (always) ou só se não existir local (missing, padrão).
$ docker run -d --name web nginx:alpine
a1b2c3d4e5f6…   « devolve o ID na hora, terminal livre
$ docker run -it --rm python:3.12-slim python
>>> print("olá do container")
olá do container   « ao sair (exit), o container é apagado sozinho por causa do --rm

Configuração: nome, portas, variáveis, pastas, rede

FlagSintaxe / valorO que faz
--name--name meu-siteDá um nome único ao container (senão o Docker inventa um, tipo keen_blackwell). Nomes facilitam stop, logs, rm.
-p-p 8080:80Publica porta: formato HOST:CONTAINER. A porta 80 do container passa a responder na 8080 da sua máquina. Variações: -p 127.0.0.1:8080:80 (só o próprio host acessa), -p 8080:80/udp (protocolo UDP), -P (maiúsculo, publica todas as portas do EXPOSE em portas aleatórias do host).
-e-e CHAVE=valorDefine variável de ambiente dentro do container (ex.: -e POSTGRES_PASSWORD=segredo). Sem =valor, copia a variável do seu shell: -e HOME.
--env-file--env-file .envLê várias variáveis de um arquivo (uma por linha, CHAVE=valor) — prático para não encher o comando de -e.
-v-v origem:destino[:opções]Monta volume ou pasta: -v dados:/var/lib/postgresql/data (volume nomeado), -v $(pwd)/site:/usr/share/nginx/html:ro (bind mount, ro = somente leitura), -v /caminho/só:/destino (absoluto).
--network--network minha-redeConecta o container a uma rede: bridge (padrão), host (usa a rede do próprio host — sem isolamento de porta), none (sem rede), ou uma rede criada por você.
-w-w /appDefine o diretório de trabalho dentro do container (onde o comando vai rodar).
--entrypoint--entrypoint /bin/shSobrescreve o ENTRYPOINT definido na imagem (o programa fixo do container).
--user / -u--user 1000:1000 ou --user nodeRoda o processo do container como outro usuário (UID:GID ou nome) — importante para não rodar como root (aula Usuário não-root).
-h-h meu-hostDefine o hostname dentro do container (por padrão é o ID curto do container).
--add-host--add-host api.local:172.17.0.5Adiciona uma entrada no /etc/hosts do container (apelido → IP).

Recursos e reinício automático

FlagSintaxe / valorO que faz
--memory / -m--memory 512m ou -m 1gLimite de memória do container — se passar, o Docker mata o processo (OOM). Aceita b, k, m, g.
--cpus--cpus 1.5Limite de CPUs (1.5 = uma CPU e meia).
--restart--restart unless-stoppedPolítica de reinício automático: no (padrão), always, on-failure[:N], unless-stopped. O daemon reinicia o container sozinho quando ele cai.

Essas flags são o equivalente em linha de comando do que no Compose vira deploy.resources.limits e restart: (veja ref-compose).

Segurança (nível 3, mas vale saber agora)

FlagSintaxe / valorO que faz
--read-onlysem valorMonta o sistema de arquivos do container como somente leitura — nada pode ser gravado (use com --tmpfs para exceções). Aula --read-only.
--tmpfs--tmpfs /tmp:rw,size=64mMonta um caminho na memória RAM (rápido e descartável) — a saída de um --read-only para apps que precisam escrever temporariamente.
--cap-drop--cap-drop ALL (ou NET_RAW…)Remove capabilities do Linux do container. ALL tira todas; combine com --cap-add para devolver só as necessárias. Aula cap-drop.
--security-opt--security-opt no-new-privileges:trueOpções de segurança extras: perfil seccomp/apparmor personalizado, no-new-privileges (impede o processo de ganhar mais privilégios via sudo/setuid), label=…. Aula seccomp.
--privilegedsem valorDá TODOS os privilégios ao container (acesso a dispositivos, módulos do kernel…). Evite — é como rodar como root no host com tudo liberado. Prefira as flags específicas (--device, --cap-add).

Logs, labels e diagnóstico

FlagSintaxe / valorO que faz
--log-driver--log-driver json-fileEscolhe como os logs do container são gravados: json-file (padrão, com rotação via --log-opt), journald, syslog, none… Aula Logging.
--log-opt--log-opt max-size=10m --log-opt max-file=3Opções do driver de log — o par clássico é o limite de tamanho e a rotação (quantos arquivos manter).
--health-cmd--health-cmd "curl -f http://localhost/ || exit 1"Comando do healthcheck definido na hora do run (sobrescreve o HEALTHCHECK da imagem). Com --health-interval, --health-retries, --health-start-period.
-l / --label-l app=web -l versao=1.0Adiciona metadados (labels) ao container — aparecem no docker inspect e dá para filtrar no ps com --filter label=app=web.
--platform--platform linux/arm64Força a arquitetura da imagem (útil em máquinas ARM rodando imagens amd64 via emulação, ou vice-versa).

Juntando as flags num exemplo real

Um run de "produção de bolso" para a API do projeto 2, com tudo comentado:

$ docker run -d \
    --name minha-api \
    -p 3000:3000 \
    -e NODE_ENV=production \
    -v /home/ana/dados:/app/dados \
    --memory 512m \
    --cpus 1 \
    --restart unless-stopped \
    --read-only --tmpfs /tmp \
    --log-opt max-size=10m --log-opt max-file=3 \
    -l app=minha-api \
    api:latest
a1b2c3d4e5f6…
$ docker ps
CONTAINER ID   IMAGE          STATUS         PORTS                   NAMES
a1b2c3d4e5f6   api:latest     Up 5 seconds   0.0.0.0:3000->3000/tcp  minha-api
$ docker inspect minha-api --format '{{.HostConfig.RestartPolicy.Name}}'
unless-stopped

O no fim de cada linha é só para continuar o comando na próxima linha no terminal — o Docker recebe tudo numa linha só.

Atenção: --read-only sozinho quebra qualquer app que grava em disco (banco de dados, uploads, cache). Nesses casos, combine com --tmpfs nos caminhos de escrita ou monte um -v nesses pontos.
A pegadinha da ordem: no docker run [OPÇÕES] IMAGEM [COMANDO], tudo depois da imagem é comando do container, não flag. Então docker run nginx:alpine -d tenta rodar o comando -d dentro do nginx (e quebra), enquanto docker run -d nginx:alpine roda em segundo plano. Flags sempre antes do nome da imagem.

Missão: rode docker run --rm hello-world e repare que, com --rm, o container é apagado sozinho depois de imprimir a mensagem (confira com docker ps -a).

Resumo

  • Sintaxe: docker run [OPÇÕES] IMAGEM [COMANDO] — flags antes da imagem; depois dela é comando interno.
  • Modo: -d (segundo plano), -it (terminal interativo), --rm (apaga ao sair), --pull always.
  • Configuração: --name, -p HOST:CONTAINER, -e/--env-file, -v, --network, -w, --entrypoint, --user, -h, --add-host.
  • Recursos: -m/--memory, --cpus, --restart.
  • Segurança: --read-only + --tmpfs, --cap-drop/--cap-add, --security-opt, evite --privileged.
  • Logs/diagnóstico: --log-driver + --log-opt, --health-cmd, -l, --platform.
  • Não lembra? docker run --help lista todas as flags da sua versão.
